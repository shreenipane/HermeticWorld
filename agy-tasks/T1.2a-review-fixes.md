## Containers (`containers.rs`, `scan.rs`)

The principle from T1.2: **magic bytes decide; the extension is only a hint.** A file that isn't really a container must fall through to the plain text path and be scanned.

- **H1. `PACK` text files are skipped.** `bytes.starts_with(b"PACK")` makes any text starting with `PACK` (for example `PACKAGE = 1`) a git pack, so a leak in it is never scanned. Require `PACK` followed by the big-endian u32 version 2 or 3. Keep the `.pack` extension out of the decision: a `.pack` file without that header is plain.
  - Test: a file whose first line is `PACKAGE_NAME = 1` and which contains the fixed lines gives a gate.
- **H2. Fake `.tar` files escape.** `is_tar` accepts any 512-byte file named `*.tar`, `*.tar.gz` and so on. The tar parser then fails, giving only an `info`, and the text is never scanned. Replace the extension logic: a buffer is tar when it has `ustar` at offset 257 or its 512-byte header has a valid checksum (sum of the header bytes with the 8 checksum bytes at offset 148 counted as spaces, compared with the octal value stored there). Old v7 tars must still open. `decompress_and_scan` uses the same content check.
  - Tests: a leak in a text file named `x.tar` (over 512 bytes) gives a gate; a gzipped text leak named `x.tar.gz` gives a gate; a v7 tar with no `ustar` magic still gives a gate at its `!/` member path.
- **H3. The `.pyc` check catches text.** Bytes 2 and 3 being `\r\n` makes a text file with a two-character CRLF first line a pyc, and its first 16 bytes are then dropped. Define `pyc_magic(bytes) -> Option<u16>`: bytes 2 and 3 are `\r\n` and the little-endian u16 from bytes 0 and 1 is in `3000..=4095` or equals `62211` (Python 2.7). A `.pyc` by name with no valid magic is still string-extracted, but from offset 0.
  - Test: a CRLF file starting `ab\r\n` with a short fixed line in its first 16 bytes gives a gate.
- **H4. String extraction uses the wrong offset on old pycs.** Use the header length from H8 in `extract_pyc_constants`.
- **H5. Tar sparse and contiguous members are silently skipped.** Read a member when its type is regular, GNU sparse or contiguous. Any other type except directories, symlinks and hard links gets an `info` finding, channel `container_skipped`.
  - Test: a contiguous-type member holding a leak gives a gate.
- **H6. SQLite tables can hide.**
  - Table names are interpolated unescaped, so a name containing `"` fails `prepare` and the table is silently skipped. Double every `"` in the name.
  - `NOT LIKE 'sqlite_%'` treats `_` as a wildcard, so a table named `sqliteleak` is excluded. Use `NOT LIKE 'sqlite\_%' ESCAPE '\'`.
  - `Err(_) => continue` and `while let Ok(Some(row))` drop errors silently. Emit a `container_error` info finding that names the table, then go on to the next table.
  - Join a row's cells with `\n`, not a space, so tier 1 line matching works across columns.
  - Tests: tables named `we"ird` and `sqliteleak`, each holding the fixed lines, give gates at the right `<db>::<table>#<rowid>` path. A row with the fixed lines in two separate columns gives a gate.
- **H7. D9 path checks include the scan root.** `check_d9_path` receives the absolute path, so a root such as `/data/swebench-copy/` makes every file a gate. Match only the path relative to the scanned root, including member suffixes. The finding's `path` stays absolute. Keep `scan_container_or_unit`'s signature and add a variant that takes the root prefix length, which `scan_tree` calls.
  - Tests: a clean tree under a tempdir whose name contains `swebench` gives 0 D9 findings; `root/swebench_dump/a.txt` still gives a `dataset_path` gate.
- **H7b. Large archives are never opened.** The `max_file_bytes` check in `scan_tree` skips every file over 64 MiB, including archives. When a file is over `max_file_bytes` but at most `max_member_bytes`, and its first 512 bytes identify a zip, tar, gzip, bzip2, xz or zstd container, scan it. Otherwise keep today's `info` finding.
  - Test: set `max_file_bytes` low in `ScanOptions` so the test stays small. An archive over it holding a leak gives a gate; a plain file over it gives the `info`.

## D3 (`bytecode.rs`)

- **H8. Old pyc headers are misread.** PEP 552's 16-byte header exists only from magic 3392 (Python 3.7). Our slice has Python 3.6 environments, where the header is magic, mtime, size (12 bytes), so today `flags` is really the mtime, and every such `.pyc` is reported as `pyc_stale` or `pyc_hash_unchecked`. Implement this from `pyc_magic`:

  | Magic | Header length | Layout |
  |---|---|---|
  | `>= 3392`, except 62211 | 16 | magic, flags, then mtime and size or the hash |
  | `3210..=3391` | 12 | magic, mtime, size |
  | anything else valid, including 62211 | 8 | magic, mtime; source size isn't checked |

  A file with no valid magic or too short for its header gets an `info` finding, channel `pyc_invalid`, and not an early empty return. Read the header so a short `read` can't truncate it.
  - Tests: fresh and stale 12-byte pycs (magic 3379); a fresh 8-byte pyc (62211) with a different source size stays fresh; a too-short file gives `pyc_invalid`.
- **H9. Dotted module names.** `foo.bar.cpython-36.pyc` is mapped to `foo.py`. Strip `.pyc`, then an optional `.opt-N`, then the final `.tag`.
  - Tests: `a.b.cpython-36.pyc`, `a.cpython-36.opt-1.pyc`.

## Winnowing (`winnow.rs`, `fingerprint.rs`)

- **H10. Line counting in triple-quoted strings.** The `\\` branch jumps two bytes without counting a newline, so `\` at a line end in a docstring shifts every later token's line, and the fingerprint range lands on the wrong code. Count it.
  - Test: tokens after a triple-quoted string containing a backslash-newline carry the correct `line`.
- **H11. Baseline subtraction uses selected hashes only.** T1.2 says to subtract every winnow hash that **occurs** in the base tree. Only hashes the base's own winnowing selected are collected, so a k-gram present at the base but not selected there survives. Collect every k-gram hash of every base file. Add a public `kgram_hashes` in `winnow.rs` and use it from both `winnow_tokens` and the base walk.
  - Test: build a post-fix slice whose selected k-gram exists at the base but wasn't selected by the base's winnowing, and assert it's subtracted. Use `winnow_hashes` directly to find such a case deterministically.

Comments.** T1.2 deleted two explanatory comments in `fingerprint.rs` that had nothing to do with its change: `// Decode the way the scanner does (lossy UTF-8, binary skipped), so every text unit the scanner can see at the base is also subtracted here.` and `// line: 1 / (1 + count)` with `// window: minimum raw weight of its lines`. Restore them.
