## Part A: request policy (`anthropic.rs`, default deny)
Adapter version constant `ANTHROPIC_ADAPTER_VERSION = "2026-11-1"`; recorded in every log line.
- **Endpoints:** `POST /v1/messages` and `POST /v1/messages/count_tokens` only. Everything else: 404 with a standard error body.
- **Headers accepted from the agent:** `anthropic-version` (must equal a configured value), `anthropic-beta` (each comma-separated flag must be in a configured allow-list; default empty), `content-type: application/json`. The agent's `x-api-key`/`authorization` are ignored and never forwarded; the gateway adds its own key upstream. All other headers are dropped.
- **Body:** parse into typed Rust structs with `#[serde(deny_unknown_fields)]` at every level, then **rebuild** the upstream JSON from the structs (never forward the original bytes). Allowed top-level fields: `model` (must be in the pinned set from config), `messages`, `system` (string or array of text blocks), `max_tokens`, `temperature`, `top_p`, `top_k`, `stop_sequences`, `stream`, `metadata.user_id`, `tools` (client tools only: `name`, `description`, `input_schema`, optional `cache_control`), `tool_choice`, `thinking` (`type` `enabled` with `budget_tokens`, or `disabled`). Content blocks allowed: `text`, `image` and `document` **with `source.type == "base64"` only**, `tool_use`, `tool_result` (content string or text/image blocks), `thinking` and `redacted_thinking` (passed back as received), each optionally with `cache_control: {"type": "ephemeral"}`.
- **Rejected with a 400 invalid_request_error naming the reason:** any provider-hosted/server tool (a tool with a `type` field, e.g. web search, web fetch, code execution, computer use, MCP connectors), `mcp_servers`, `container`, URL or file-ID sources, `previous_response_id`-like or stored-state fields, batch or background modes, unknown fields, unlisted beta flags, models outside the pinned set.
- **Nonce (TR-GW-6):** generate one 128-bit random nonce per run at startup (`getrandom`), hex. Prepend `"[run-nonce <hex>]\n"` as the first text of the system prompt (create the system prompt when absent; when `system` is an array, insert a new first text block). Never derive anything from time.

## Part B: response policy
- **Headers to the agent:** only `content-type`, `content-length`, `content-encoding`, and `retry-after` converted to integer seconds (an HTTP-date or RFC 3339 value is converted relative to the upstream response's own `date`, rounded up, minimum 0). `date` is replaced with **guest time** (`T_clock + elapsed since gateway start`, IMF-fixdate). All rate-limit headers, request IDs and CDN headers are dropped and written to the host log.
- **Body timestamps (JSON and every SSE event):** rewrite any field named `created`, `created_at`, `updated_at`, `expires_at` holding a number (Unix seconds) or an RFC 3339 string to guest time in the same format. Walk the whole JSON.
- **Errors (TR-GW-5):** for any non-2xx upstream status, replace the body with a standard Anthropic-shaped error `{"type":"error","error":{"type":<recognised type or "api_error">,"message":<standard text for that type>}}` where the recognised types are `invalid_request_error`, `authentication_error`, `permission_error`, `not_found_error`, `request_too_large`, `rate_limit_error`, `api_error`, `overloaded_error`; keep the status. In a stream, an `event: error` is replaced the same way. Originals go to the host log only.
- **Streaming:** parse SSE event by event (bounded line and event sizes), sanitise each event's JSON, and re-emit. Count output tokens from `message_delta` usage.

## Part C: quotas, logs, front end
- **Quotas (TR-GW-7):** per-run caps on requests, input tokens, output tokens (from `usage`), concurrent requests, and wall time, from config. A breach returns a standard error to the agent and puts the gateway into a terminal `limit_exceeded` state (all later requests refused); it is recorded in the run log.
- **History-consistency log (TR-GW-8):** for each request, hash the conversation prefix (canonical JSON of `system` + each message, chained with BLAKE3 if available in the workspace, else SHA-256 from `sha2`). A request whose message list neither extends a conversation already seen nor starts a new one (first message only) is recorded as a `history_rewrite`; rewrites are counted, never rejected.
- **Host log:** JSON lines with request summary, upstream status, dropped headers, original error bodies, quota counters, adapter version. Never log the API key.
- **Front end:** `hermetic-gateway --config FILE --listen 127.0.0.1:PORT --t-clock RFC3339`; config JSON holds `upstream_base_url` (default `https://api.anthropic.com`), `anthropic_version`, `allowed_betas`, `pinned_models`, quota values, `log_dir`, and `api_key_file` (read once into memory; the file path, never the key, may be logged).

## Tests (offline; a mock upstream built with tiny_http on 127.0.0.1 in the test)
- Allowed request is rebuilt (field order and content verified at the mock); unknown field, server tool, URL image source, file-ID document, unlisted beta, unpinned model and wrong endpoint are each rejected with the right error and never reach the mock.
- The agent's API key header is not forwarded; the configured key is.
- Nonce: present as the first system text, 32 hex chars, same for every request in a run, different across two gateway instances.
- Response headers filtered; `date` replaced; `retry-after` conversion for seconds, HTTP-date and RFC 3339 inputs.
- Body timestamp rewrite in JSON and in a multi-event SSE stream; an SSE `error` event is replaced.
- Non-2xx bodies (with timestamps and free text) replaced by the standard error with the recognised type; an unrecognised type becomes `api_error`.
- Each quota triggers `limit_exceeded` and later requests are refused.
- History log: extending a conversation is not a rewrite; editing an earlier message is counted as one.
- Hostile input: huge bodies (cap request size, e.g. 32 MiB, and return 413), deeply nested JSON (bounded depth), invalid UTF-8, malformed SSE from the mock: no panic.
