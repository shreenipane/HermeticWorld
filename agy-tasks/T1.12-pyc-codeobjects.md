## Part A: fingerprint side (`fingerprint.rs`)
For each hunk of the gold patch in a `.py` file, find the **enclosing function** (the nearest `def`/`async def` at a lower indentation above the hunk in the fixed file; for module-level code use the name `<module>`; for a class body, the class name). Do this for the base version of the file (from the base tree) and the fixed version (base plus patch; `FingerprintSet::from_task` already has both views or can build them).

For that function in each version, collect its **symbol set**: every identifier token, every attribute name after a `.`, and every literal (string contents without quotes and prefix; integer and float literals as written), using `crate::winnow::tokenize`; exclude Python keywords. Then:
- `added = fixed_symbols − base_symbols`; `removed = base_symbols − fixed_symbols`.
- Store per hunk a `PycFunctionFingerprint { function_name, added, removed }` when `added ∪ removed` is non-empty. Drop symbols that are in a small built-in stop list (`self`, `cls`, `None`, `True`, `False`, `0`, `1`, `""`).

## Part B: `.pyc` side (`bytecode.rs` or a new `pyc_marshal.rs`)
Parse the marshal stream after the header into code objects without a full unmarshal of every type you don't need, but correctly skipping every marshal type so offsets stay right: handle the type codes for None, True, False, StopIteration, Ellipsis, int (`i`), long (`l`), float (`f`, `g`), complex (`x`, `y`), strings (`s`, `t`, `u`, `a`, `A`, `z`, `Z`), tuples (`(`, `)`), lists, dicts, sets, frozensets, refs (`r`) with the `FLAG_REF` bit (0x80) and the ref table, and code objects (`c`). Code-object layouts differ by version: support CPython 3.6 through 3.13 using the magic number from `pyc_magic` (3.8 adds posonlyargcount; 3.11 changes to co_localsplusnames, co_localspluskinds, co_qualname, co_exceptiontable). For each code object, recursively, collect `co_name` (and `co_qualname` when present) and its **symbol set**: `co_names`, `co_varnames`/`co_localsplusnames`, `co_freevars`, `co_cellvars`, and the string, int and float constants in `co_consts` (not nested code objects, which are their own entries).

Unparseable input: fall back silently to today's behaviour (no new finding), never an error that hides the existing tiers.

## Part C: matching (D3b, channel `binary_pyc_function`)
For a code object whose `co_name` equals a hunk fingerprint's `function_name` (for `<module>`, the top-level code object):
- `hit_added` = |added ∩ pyc_symbols|, `hit_removed_absent` = |removed − pyc_symbols|.
- confidence = (hit_added + hit_removed_absent) / (|added| + |removed|).
- When `added` is non-empty: **Gate** when confidence ≥ `opts.binary_threshold` (0.60, unchanged) and at least one added symbol is present.
- When `added` is empty (a pure deletion): absence of names is weak evidence (an unrelated function of the same name also lacks them), so report **Review**, not Gate, when confidence ≥ 0.60, and say so in the evidence.
- Evidence: the function name and up to 5 matched symbols.

Wire it in `ContainerScanner::scan`'s `Pyc` branch through the sink (add a `UnitSink` method, e.g. `pyc_code_objects(path, &[PycCodeObject])`), so `index` stores it too: a new index record (next free tag; bump `FORMAT_VERSION` and keep reading older versions) holding each code object's name and its symbols hashed with `sha256_u64`; `query` matches against hashed fingerprint symbols exactly as scan does.
