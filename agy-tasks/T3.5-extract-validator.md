# Task T3.5: `hermetic-extract`: record stream and host-side validator (TR-EXT-5, TR-EXT-6)

You are the coding agent on Hermetic World (it seals benchmark worlds so that no post-cutoff or host information leaks to an agent). After a run, the agent's disk is never mounted on the host. A small ExtractorVM reads it and streams records to the host. The agent controlled that disk, so **every byte of the stream is hostile**. This task builds the stream format and the host validator that turns it into a safe work tree. The ExtractorVM side is a later task.

## What to build
1. **Record format (TR-EXT-5).** Length-prefixed records: type (regular file, directory, deletion, end-of-stream), path, mode, size, SHA-256, bytes. Fixed-width little-endian header fields, a magic and version at stream start, and an end record carrying the record count and total bytes. Provide an encoder (used by tests and later by the ExtractorVM) and a streaming decoder that never allocates from an untrusted length: every length is checked against a named cap before any buffer grows, and file bytes are streamed in bounded chunks. Truncated, oversized, trailing-garbage and unknown-type inputs are errors, never panics.
2. **Validator (TR-EXT-6)**, streaming from any `Read` into an output directory:
   - accepts regular files, directories and deletions only; anything else (symlink, device, FIFO, socket, hard-link record) is rejected;
   - paths: relative only, UTF-8, no empty component, no `.` or `..`, no NUL, no backslash, no absolute or drive-like prefix, bounded depth and length; a path may not pass through a component that the stream itself declared as a regular file; duplicate records for one path are rejected; case-fold collisions are reported;
   - quotas: per-file bytes, total bytes, file count, directory count, all named caps taken from a config struct; exceeding any stops the validation with a typed error;
   - the declared size and SHA-256 must match the bytes received;
   - mode: only the executable bit survives; files are written 0644 or 0755 and directories 0755, never setuid, setgid or sticky;
   - writing: the output directory must be empty and owned by the caller and is opened once; everything is created relative to held directory descriptors with no-follow and exclusive-create semantics, so nothing can be written outside it even if the directory is tampered with during the run; on any error the partial output is removed and nothing is published. Publication of the finished tree is atomic (build in a private sibling directory, rename).
   - task class: `patch` accepts changes only inside the declared repository directory; `artifact` accepts only the declared paths; `state` accepts an empty stream only.
3. **Test-infrastructure restore.** Given the pristine base tree (read-only input) the validator's result must not let the agent change test infrastructure: records touching test files (by the task's declared test paths), `conftest.py`, `pytest.ini`, `tox.ini`, `sitecustomize.py`, `usercustomize.py`, `*.pth`, in-tree `*.egg-info` and `*.dist-info` are dropped and listed, and those files are taken from the base tree; in `setup.cfg`, `pyproject.toml` and `tox.ini`-style files the test-runner sections (`[tool:pytest]`, `[pytest]`, `[tool.pytest.ini_options]`) and `pytest11` entry points are restored from the base version while the rest of the agent's file is kept (line-based section handling with a documented, conservative rule: if the file cannot be parsed safely, the whole file is restored from base and listed).
4. **Shadowing flag.** New top-level modules or packages (a new `name.py` or `name/__init__.py` at a top-level import root) whose name equals a standard-library module (embed a fixed sorted list of Python 3 standard-library top-level names as a data file with a note of its Python version) or a name in the supplied installed-package list are flagged in the report (not rejected).
5. **Report.** Deterministic JSON: accepted, dropped and restored paths with reasons, flags, totals, and the SHA-256 of the resulting tree manifest (sorted path, mode, hash lines). Known-answer test.
6. **Binary** `hermetic-extract-validate --stream FILE --base DIR --out DIR --class patch|artifact|state --config FILE`: exit 0 accepted, 2 rejected, 1 error.

Tests must include: every rejection rule above; a stream that tries path traversal through a directory record replaced by a file record; size and hash mismatches; quota boundaries (exactly at the cap passes, one over fails); a truncated stream at every header offset (loop over cut points) never panics; partial output is removed on failure; restore rules; shadowing flags; the known-answer report.
