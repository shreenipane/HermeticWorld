## H1. The git leak check flags legitimate history: a false positive (must fix)

**What happened live.** `seal-images --only pytest-dev__pytest-6202` failed with `gold_lines_found_in_git is 1` on the **sealed** image. The reviewer traced the matching line, `return ".".join(parts)`, to commits from **2008** (`9eb1d5538`, `abc8cf09a`), eleven years before the base commit. Pre-base history is legitimately visible to the agent, so this is not a leak. Baseline subtraction only covers the base **tree**, but the check scans **every blob in history**.

It has a second problem: it reads the whole object store into memory. That's gigabytes for Django or matplotlib.

**Fix.** The only objects that can leak are those **not reachable from the base**.
- In the in-container measurement, compute `reachable = set(git rev-list --objects --no-object-names <base>)` and `unreachable = all objects (cat-file --batch-all-objects) − reachable`.
- Report:
  - `objects_not_reachable_from_base`: a count by type, e.g. `{"commit": 1, "tree": 0, "blob": 0, "tag": 1}`;
  - `gold_lines_found_in_unreachable`, replacing `gold_lines_found_in_git`: scan the content of **unreachable blobs, commits and tags only**. Commit and tag messages can carry text too.
- **Stream** `git cat-file --batch`: write the SHAs, then read each header and exactly `size + 1` bytes from `p.stdout` incrementally. Never call `communicate()` on the whole output.
- **Verification** (`verification_problems`):
  - replace the `gold_lines_found_in_git` rule with `gold_lines_found_in_unreachable == 0`;
  - add a rule that the sealed image's unreachable objects may only be **tag objects**. Kept annotated tags are vetted by the sealer (ancestor, tagger date ≤ `T_clock`), and `rev-list --objects` doesn't list tag objects. So `commit`, `tree` and `blob` counts must all be 0.
- **Regression test.** In the fake image, add a line of at least 12 characters to c1's file, remove it in c2, and add the same line to the hand-written `test.patch`. After sealing, the line exists only in pre-base history: verification must **pass**, and `gold_lines_found_in_unreachable == 0`. The existing dangling-commit line must still be found in the **before** report.

## H2. A failed seal leaves no record (must fix)

When verification fails, nothing is written, and only stderr says what went wrong.
- **Fix:** always write `seal/report.json`, with a new top-level `"status"` of `"sealed"` or `"failed"` and `"problems"` (the list, empty on success). On failure, write the report and **then** raise `ImageSealError`.
- **Test:** an end-to-end run where verification fails (patch `verification_problems` to return a problem). `report.json` exists with `status: "failed"`, and the error is raised.

## H3. `--only` keeps only the last value (must fix)

`--only` uses `nargs="*"` with the default `store` action, so `--only a --only b` processes only `b`.
- **Fix:** use `action="append"`.
- **Test:** `main([... "--only", "a", "--only", "b"])` processes both. Patch `seal_image` to record its calls.

## H4. The CLI status column is fake (must fix)

It always prints `unsealed→sealed`, whatever happened, and `→` can raise `UnicodeEncodeError` on a cp1252 Windows console.
- **Fix:** print ASCII only: `instance_id  head_was_base  extra_commits  gold_lines  status  sealed_image`, where `status` comes from the report (`sealed` or `failed`). On failure, also print the problems.

## H5. Duplicated helpers and private cross-module imports (cleanup)

- `_rmtree` and `_make_writable_and_retry` are copied from `repo_sealer.py` into `image_sealer.py`, and `__main__.py` imports the private `_rmtree`. Make one public `rmtree_force(path)` in `repo_sealer.py` and use it everywhere.
- Rename `http._atomic_write_bytes` to the public `atomic_write_bytes`, since `intake.py` imports it.

## H6. Unspecified fallback in `gold_lines` (cleanup)

`gold_lines` silently falls back to `task_dir/<name>` when `staging/<name>` is missing. Remove that. A missing staging patch counts as an empty patch.

## H7. An unknown `--only` ID is ignored silently (from CodeRabbit, verified)

A mistyped `--only` ID, or one with no task directory, is skipped, and the command exits 0, so a batch script sees success with nothing sealed.
- **Fix:** print an error for every requested ID with no matching task directory, and exit 1.
- **Test:** `--only does-not-exist` exits 1, and the error names the ID.
