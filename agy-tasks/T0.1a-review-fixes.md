## Correctness and safety (must fix)

### F1. `run_git` inherits `GIT_*` variables from the caller
`_git_env` starts from `os.environ`. If the caller has `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_*`/`GIT_CONFIG_VALUE_*` or `GIT_NAMESPACE` set, git silently operates on a different repo, sees extra objects, or gets injected config. This happens, for example, when it runs from inside a git hook. For a sealer that is a leak path.
- **Fix:** drop **every** inherited variable whose name starts with `GIT_`. Then apply the caller's explicit `env` argument. Then apply the isolation variables last.
- **Test:** with `monkeypatch.setenv("GIT_DIR", str(<some other repo>/.git))`, `run_git(["rev-parse", "--absolute-git-dir"], cwd=repo)` must return `repo`'s git dir, and `seal_repo` must still produce a clean seal.

### F2. Annotated tags with no tagger date are kept (fails open)
If `%(taggerdate)` is empty, the tag skips the date check and is kept. Old repos do have tagger-less annotated tags. We can't show such a tag is ≤ `T_clock`, so the sealer must fail closed.
- **Fix:** drop it with the new reason `"no_tagger_date"`.
- **Test:** create a tag object without a `tagger` line by piping a hand-written tag body into `git mktag --no-strict`. This is verified to work: it warns `missingTaggerEntry` but creates the object. Plain `mktag` and `hash-object -t tag` both refuse. Point the tag at c1, add it with `git update-ref refs/tags/<name> <sha>`, and expect `dropped_tags[name] == "no_tagger_date"`.

### F3. `%(refname:short)` is ambiguous
If a branch and a tag share a name, `refname:short` returns `tags/<name>`. The code then builds `refs/tags/tags/<name>`, and the fetch fails.
- **Fix:** read `%(refname)` and strip the `refs/tags/` prefix.
- **Test:** add a branch named the same as a kept tag in a test repo. Sealing must succeed and keep the tag.

### F4. Parse tagger dates without ISO strings
`datetime.fromisoformat` on git's `iso-strict` output breaks on Python 3.10 when git prints `Z`.
- **Fix:** use `%(taggerdate:unix)` and `datetime.fromtimestamp(int(...), tz=timezone.utc)`. Also set `requires-python = ">=3.11"` in `pyproject.toml`, because the CLI parses `--t-clock` with `fromisoformat`.
- **Test:** a tag dated **exactly** `t_clock` is kept (the rule is ≤).

## Performance (must fix: real repos have hundreds of tags)

### F5. One process per tag
Django has 300+ tags. T0.1 runs `merge-base --is-ancestor` once per tag and `git fetch` once per tag, and each fetch spawns upload-pack through a shell.
- **Fix:**
  - compute the set of commits reachable from the base **once** (`git rev-list <base>`) and test each tag's commit for membership;
  - fetch the base SHA and **all** kept tag refspecs in a **single** `git fetch` call.
- **Test:** existing tests still pass, and there's a new test with a tag on the base commit itself (kept).

Three of them (the Python 3.10 `Z` suffix in `repo_sealer.py`, `__main__.py` and `test_cutoffs.py`) are resolved by F4, which raises `requires-python` to `>=3.11` and switches tagger dates to `:unix`. Do **not** add `Z`-replacing string hacks. The other two are valid:

### F11. Ref names decoded as ASCII
`seal_repo` decodes the tag listing as UTF-8, but `verify_sealed_repo` decodes `for-each-ref` and `symbolic-ref` output as ASCII. A non-ASCII tag name then raises `UnicodeDecodeError` instead of producing a verification result.
- **Fix:** decode every git output that can contain ref names or paths as `utf-8` with `errors="replace"`. Pure hex output (SHAs) may stay ASCII.
- **Test:** an ancestor tag named `v1.0-ünïcode` is kept, and the seal verifies clean.

### F12. A failed seal leaves a populated `dest`
If anything fails after `git init` (including `VerificationError`), `dest` is left half-built. A caller that ignores the error could use a repo that failed verification, and a retry fails with "not an empty directory".
- **Fix:** wrap everything from `git init` through verification in `try`/`except BaseException`. On failure, remove what this call created: delete `dest` entirely if the function created it, or empty it if it was a pre-existing empty directory. Then re-raise.
- **Test:** patch `verify_sealed_repo` to return a problem. `seal_repo` raises `VerificationError`, and `dest` no longer exists. Repeat with a pre-existing empty `dest`: it still exists and is empty.
