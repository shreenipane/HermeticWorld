## The key refactor
`match_unit` computes a unit's hashes, then matches them. Split it:
- `UnitHashes`, made public and serialisable to the index;
- `match_unit_hashes(&UnitHashes, fp, opts, detector, channel, path)`.

`match_unit` becomes `match_unit_hashes(&compute_unit_hashes(text), ...)`, with **identical behaviour**. Every existing test must still pass unchanged.

**Hashes in the index are 64-bit:** the first 8 bytes of each sha256. At query time, convert the task's fingerprint hashes the same way before comparing. Winnow hashes are already `u64`.

## Part A: `hermetic-sealcheck index --root DIR --out FILE`
Walk the tree exactly as `scan_tree` does, with the same pruning, symlink handling, size limits and container recursion. Write one record per scanned unit:
- the unit path, root-relative, with `!/` and `#` member syntax as today;
- size, mtime and mode (for D4 later);
- for text units: `UnitHashes`, plus the builtin D9 content hits (canary, dataset host, dataset dump), which don't depend on the task;
- for binary units: the extracted exact strings, hashed to `u64`, plus the whole-token runs (`[A-Za-z0-9_]+` pieces of printable runs), hashed to `u64`;
- for package-metadata units: name and version (for D5a);
- the `info` findings the scan would have made for the unit (errors, bombs, skipped binaries), so query reports them unchanged.

**File format.** A zstd-compressed stream with a header: magic `HWIDX1`, format version, root path, unit count. Records are length-prefixed little-endian binary that you define and document in the module. Write a reader that rejects truncation, bad magic, oversized lengths and counts (cap them by the remaining bytes), and never panics.

## Part B: `hermetic-sealcheck query --task DIR --base-tree DIR --index FILE [--index FILE ...] [--root-visibility ...] [--format json|sarif]`
- Build the task's `FingerprintSet` as `scan` does.
- Stream every index's records, applying:
  - `match_unit_hashes` for tiers 1 and 3 and diff shapes;
  - the binary tier against the hashed strings;
  - D5a against the stored metadata;
  - D9 path checks, re-run on the stored paths;
  - D9 builtin content hits, from the stored flags.
- Output the same report format as `scan`.
- **Detectors that need the live tree or the task's identity are not answered from the index:** D1, D3, D6, the D9 instance-id check and external signatures. Mark this in the report: `"mode": "query"` and `"not_covered": ["D1", "D3", "D6", "D9:instance_id", "D9:external"]`.
- Binary items that hold characters outside `[A-Za-z0-9_]` can only match a stored exact string, not a run token. Document that limit.

## Tests (all offline)
- **Equivalence**, the main test: for each of several trees, `scan` findings must equal `query` findings, restricted to the covered detectors and sorted the same. The trees are:
  - a planted leak in plain text;
  - a reformatted copy;
  - a leak in a zip, a tar.gz and a nested archive;
  - a SQLite db;
  - a minified bundle and an ELF with the fix's identifiers;
  - newer package metadata inside a wheel;
  - a clean tree.
- **Round trip:** index, read it back, and every record is identical.
- **Hostile index files, one test each, none may panic:** truncated; bad magic; a length past the end; a count larger than the file; a corrupt zstd frame.
- **Two indexes queried together** give the union of their findings.
- **`#[ignore]`d perf test:** build a 50 MB, 5,000-file tree, index it, then time `query`. The budget is under 5 s in release. Print both times.
