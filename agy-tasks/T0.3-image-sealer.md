## Part A: `python/hermetic_slice/image_sealer.py`

### A1. `gold_lines(task_dir: Path, sealed_repo: Path, base: str) -> list[str]`
These are the secret lines to search for: §5.2 tier 1, simplified.
- Take the added lines (`+` but not `+++`) from **both** `staging/gold.patch` and `staging/test.patch`.
- Strip whitespace and keep lines of at least 12 characters.
- **Baseline subtraction:** drop any line that already occurs anywhere in the base tree. Use `git grep -F -x` in `sealed_repo` at `base`, run through `run_git`. Match the whole stripped line, and remember that grep matches lines with indentation, so compare stripped lines. You may instead build a set of stripped lines from `git ls-tree -r` and `git cat-file --batch`; that's simpler and exact.
- Return a deduplicated, sorted list.

### A2. `measure(image: str, task: dict, lines: list[str]) -> dict` (the "before" report)
Run one container from `image` and return:
- `head`, `head_is_base`, `branch`;
- `extra_commits`: a list of `{sha, author, author_date, subject}` for `<base>..HEAD`;
- `refs_total`, `refs_not_ancestor_of_base`: refs whose target isn't an ancestor of or equal to the base;
- `commits_in_store_not_reachable_from_base`: compare every commit object (`cat-file --batch-all-objects`) with `rev-list <base>`;
- `fix_commits_present`: which `task["dates"]["fix_commits"]` SHAs exist;
- `remotes`, `reflog_entries`, `stash_entries`, `git_meta_files_present`: which of `ORIG_HEAD`, `FETCH_HEAD`, `logs`, `COMMIT_EDITMSG` and non-empty `hooks` exist;
- `tracked_modified_vs_base`: a count;
- `gold_lines_found_in_git`: how many of `lines` occur in any git object's content;
- `gold_lines_found_in_tree`: how many occur in any file under `/testbed`, excluding `.git`;
- `newest_mtime`: the newest file mtime under `/testbed`, as ISO 8601;
- `cache_sizes`: bytes for `/opt/miniconda3/pkgs`, `/root/.cache` and `/root/.bash_history`, where present.

Pass the gold lines into the container on **stdin** (`run_docker(..., input=...)`), never as arguments. Write the in-container script as one bash program, kept in a module-level constant, that prints a single JSON object at the end. The Python side parses it. You may use `python3` or `python` inside the container for the JSON, since the images ship Python.

### A3. `seal_image(task_dir: Path, work_dir: Path, *, tag: str | None = None) -> dict`
1. Read `task.json` and get the image, base and `t_clock`.
2. **Extract the original repo:** `docker create` the image, `docker cp <container>:/testbed/.git <work_dir>/orig/.git`, then `docker rm`. The extracted `.git` is untrusted input; only read it.
3. **Seal it** with T0.1's `seal_repo(src=<work_dir>/orig, base_commit=<base>, dest=<work_dir>/sealed, t_clock=<t_clock>)`. `src` is a directory containing `.git`, so `seal_repo` works unchanged.
4. Compute `gold_lines` against `<work_dir>/sealed` and run `measure` on the original image to get `before`.
5. **Build** the sealed image. Write a `Dockerfile` into a build context in `work_dir` (`ARG` isn't needed; write the FROM line directly):
   ```
   FROM <original image>
   RUN rm -rf /testbed/.git /root/.cache /root/.bash_history \
    && (conda clean --all --yes || true)
   COPY sealed.git /testbed/.git
   ```
   - Copy `<work_dir>/sealed/.git` to `<context>/sealed.git`.
   - After the copy, the sealed repo's branch is `sealed` and points at the base. Set the image's `/testbed` `HEAD` to that branch: it already is, through the sealed repo's `HEAD`.
   - Tag the result `tag`, defaulting to `"hermetic/" + instance_id.lower() + ":sealed"`.
   - Run `docker build` with `--network none`, so the build itself can't fetch anything.
6. **Verify** by running `measure` on the sealed image to get `after`. Then fail with `ImageSealError` unless all of these hold:
   - `head_is_base`;
   - `extra_commits == []`;
   - `refs_not_ancestor_of_base == 0`;
   - `commits_in_store_not_reachable_from_base == 0`;
   - `fix_commits_present == []`;
   - no remotes, no reflog entries, no stash;
   - `git_meta_files_present == []`;
   - `tracked_modified_vs_base == 0`;
   - `gold_lines_found_in_git == 0`.

   `gold_lines_found_in_tree` must be 0 too, unless the file is in the base tree, which baseline subtraction already handles. So simply require 0.
7. Write `<task_dir>/seal/report.json`, sorted keys and 2-space indent, containing: `schema: "hermetic-slice-seal/v1"`, `instance_id`, `original_image`, `sealed_image`, `sealed_image_id` (from `docker image inspect`), `seal_report` (T0.1's `SealReport` as a dict), `gold_lines_checked: len(lines)`, `before`, `after`, and `notes`. `notes` must include:
   - `"file mtimes not normalised (Phase 0, clock: real)"`;
   - `"original layers still exist under the sealed image; deleted files are hidden from the container by overlayfs but present in the image tarball (Phase 0 gap; flattened rootfs comes with mke2fs in Phase 2)"`;
   - a note when `len(lines) == 0`, because the check is then vacuous: `"no checkable gold/test lines after baseline subtraction"`.
8. Return the report dict.
