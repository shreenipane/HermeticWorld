## Module `hermetic_slice/e3.py` and three CLI subcommands

### `e3-basetrees --tasks-dir DIR --out DIR [--only ID ...]`
- For each task, extract `/testbed` from image `hermetic/<id>:sealed` into `<out>/<id>/`, **without `.git`**. Use `docker create`, then `docker cp`, then `docker rm`, through `dockerutil`.
- Do one task at a time. Skip a task whose output already exists.
- Write `<out>/<id>/../<id>.basetree.json` with the file count and the sha256 of the sorted relative file list.

### `e3-build --tasks-dir DIR --base-trees DIR --out DIR [--seed N]`
- Writes one directory per case: `<out>/cases/<case_id>/root/...`, the files to scan, plus `<out>/cases/<case_id>/case.json`: `{case_id, task_id, kind: "positive"|"negative", variant, expected: "gate"|"clean", notes}`.
- Writes `<out>/corpus.json`: seed, tool version, and every case with the sha256 of its sorted file contents.
- The same seed always gives a byte-identical corpus. Use `random.Random(seed)` only.

**Positive variants, per task** (expected `gate`):

| Variant | Content of `root/` |
|---|---|
| `p01_postfix_file` | Every file the gold patch touches, after applying it, at its repo-relative path. Apply the patch to copies of only the touched base files, with `git apply` run in a temp dir that's not a repo |
| `p02_reformatted` | Each changed hunk's region of the post-fix file, 10 lines either side, with comments removed, blank lines dropped and indentation stripped |
| `p03_patch_file` | `staging/gold.patch` as `fix.patch` |
| `p04_regenerated_diff` | A diff of base and post-fix files from `difflib.unified_diff` with 1 context line and no `index` lines, as `fix.diff` |
| `p05_hunk_in_prose` | The added lines of the first hunk, pasted between two paragraphs of filler prose in `notes.txt` |
| `p06_zip` | The `p01` files in `leak.zip` |
| `p07_tar_gz` | `fix.patch` in `leak.tar.gz` |
| `p08_nested` | A zip holding the `p01` files, inside a `.tar.gz` |
| `p09_sqlite` | A SQLite db with each `p01` file's text in a TEXT cell |
| `p10_hidden_tests` | The added lines of `staging/test.patch`, as `tests_leak.py` |
| `p11_pyc` | `py_compile` of each `p01` `.py` file, as `.pyc` only. Skip the variant when no touched file is `.py` |

**Synthetic tasks.** Build 3 deletion-only and 3 one-character-fix tasks in a generated mini repository. Use realistic generated Python modules of about 300 lines. Each gets its own task directory (`task.json`, `staging/`, `agent/`) and base tree under `<out>/synthetic/`, so sealcheck can run on them like a real task. Each gets `p01`, `p03` and `p04`, plus the negatives below.

**Negative variants, per task** (expected `clean`):

| Variant | Content of `root/` |
|---|---|
| `n01_prefix_files` | The touched files at the base (before the fix) |
| `n02_base_sample` | 200 base-tree files sampled with the seed, at their paths |
| `n03_cross_task` | Another task's `p01` and `p03` content, scanned with this task's fingerprints. Pair each task with the next in sorted order |

### `e3-run --corpus DIR --tasks-dir DIR --base-trees DIR --sealcheck BIN --out DIR [--blind DIR]`
- For each case, run `BIN scan --task <task dir> --base-tree <base tree> --root <case>/root --root-visibility agent_visible --format json`, with a 300 s timeout, one case at a time.
- Synthetic tasks use their own task directory and base tree.
- **A case is called `gate`** when any finding is `severity == "gate"` and `visibility == "agent_visible"` with detector `D0`, `D2` or `D3b`. Those are the fingerprint detectors E3 measures. Other detectors' findings are recorded, not scored.
- Write `<out>/results.jsonl` (one line per case: label, call, exit code, the scored findings' channels, wall time) and `<out>/metrics.json`:
  - TP, FP, TN and FN, precision, recall, and Wilson 95% intervals;
  - computed overall, per variant, per task, and for the synthetic set.
- Also write `<out>/metrics.md` with the same numbers as tables.
- A timeout or crash counts as a call of `error`. It's reported per case and counted against recall for positives and against precision for negatives.
- **`--blind DIR`:** the same case layout, but with labels in `DIR/labels.json`, read only after every blind case has been scanned. This is for leaks seeded by a second person. Report blind metrics separately.
- The exit code is 0 unless the harness itself fails. This is a measurement, not a gate.
