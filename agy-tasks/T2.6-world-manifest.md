## Part A: the manifest type
`WorldManifest` with serde, `deny_unknown_fields`, every field from §13.1:
- Identity: `spec_version` (string, "hermetic-world/v1"), `task_id`, `task_class` (`dated` | `undated`), `seal_level` (`strict` | `repo_only`).
- Cutoffs: `t_world`, `t_clock` (RFC 3339 UTC), `base_commit` (40-hex, optional for undated), `pkg_cutoff`.
- Content: `repo_tree_digest`, `rootfs_digest`, `packages` { `closure_root`, `baseline_month` ("YYYY-MM"), `baseline_root` }, `web` (optional) { `index_month`, `capture_index_root` }.
- Substrate: list of { `name`, `version`, `digest`, `date` }, `substrate_at_t` (`full` | `partial` | `none`), `exemptions` (list of { `package`, `reason` }).
- Network: `dns_table` (sorted list of host names), `world_ca_cert_sha256`, `trust_store_paths` (sorted list).
- Run spec: `env` (sorted map), `workdir`, `user`, `entrypoint` (list of strings), `resources` { `vcpus`, `memory_mib`, `disk_mib`, `wall_time_s` }.
- Evidence: `sealcheck_report_digest`, `dispositions` (list of { `kind`: `repaired` | `excluded`, `detector`, `detail` }).
Digests are lowercase hex with an algorithm prefix: `blake3:<64 hex>` or `sha256:<64 hex>`. Validate on load: formats, sorted-and-unique lists, RFC 3339 times with `t_clock >= t_world`, month format. A validation failure lists every problem, not just the first.

## Part B: `world_root`
- **Canonical form:** each leaf is `(path, value)` where `path` is the JSON-pointer-like field path (`/cutoffs/t_clock`, `/substrate/2/digest`, `/run_spec/env/PATH`) and `value` is the canonical JSON encoding of the scalar (strings as JSON strings, numbers as integers; no floats anywhere in the manifest). Leaves sorted by path (byte order).
- **Leaf hash:** `BLAKE3("hw-leaf\0" || len(path) u32 LE || path || len(value) u32 LE || value)`.
- **Tree:** binary Merkle tree over leaf hashes in sorted order; internal node `BLAKE3("hw-node\0" || left || right)`; an odd node at a level is promoted unchanged; the empty tree is `BLAKE3("hw-empty\0")`. `world_root = "blake3:" + hex(root)`.
- Provide `inclusion_proof(path)` and `verify_inclusion(root, path, value, proof)` so an attestation can prove a single field (e.g. `t_clock`) without the whole manifest.
- Optional fields that are absent produce no leaf; an empty list produces no leaf (document both).

## Part C: tree digests
`digest_tree(dir) -> Result<String>` for `repo_tree_digest` and similar: walk sorted by byte path, never follow symlinks (a symlink contributes its target string), include each entry's relative path, kind (file, dir, symlink), executable bit (not other mode bits, not times, not owner), and for files the BLAKE3 of the contents (streamed). Special files are an error naming the path. Compose entries into the same leaf/Merkle scheme with domain tag `"hw-tree\0"`. `digest_file(path)` = `blake3:` of the contents, streamed.

## Part D: CLI `hermetic-manifest`
- `root --manifest FILE`: validate, print `world_root`.
- `verify --manifest FILE --expect ROOT`: exit 0 if it matches, 1 with the computed root otherwise.
- `prove --manifest FILE --path /cutoffs/t_clock`: print the leaf value and the proof as JSON; `check-proof --root ROOT --path P --value V --proof FILE`.
- `digest-tree --dir DIR` and `digest-file --file F`.

## Tests (offline)
- The same manifest serialised with fields in different orders, and env maps in different insertion orders, gives the same root; changing any single field (one test per group) changes it.
- Known-answer test: a small fixed manifest whose root you compute and hard-code, so the scheme cannot drift silently.
