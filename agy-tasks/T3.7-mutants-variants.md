# Task T3.7: `hermetic_mutants`: test-variant generation by syntax-tree rewriting (TR-GR-8, generation half)

You are the coding agent on Hermetic World (it seals benchmark worlds so that no post-cutoff or host information leaks to an agent). Differential grading runs the hidden tests in rewritten forms: **equivalents** (same meaning, different text, so a forger that pattern-matches test text is caught when results differ) and **mutants** (an assertion changed to a value that must fail, so a forger that makes everything pass is caught). ## What to build
New package `python/hermetic_mutants/` (`__init__.py`, `rewrite.py`, `pool.py`, `__main__.py`) and tests in `python/tests/test_mutants.py`. Use only the standard library `ast` module (`ast.parse`, `ast.unparse`); never import, compile-and-run or execute the test code being rewritten.

1. **Parsing.** Read a Python test file as bytes (size cap, must decode as UTF-8, bounded syntax-tree depth and node count checked after parsing, `ast.parse` errors and `RecursionError`/`MemoryError` converted to one typed error).
2. **Assertion sites.** Find assertion sites inside test functions (`def test_*` at module level or in `class Test*`): plain `assert` statements with a comparison, and `self.assertEqual`/`assertTrue`/`assertFalse`/`assertIs`/`assertIn` calls. Each site gets a stable id: function qualified name plus the index of the site in that function (never a line number alone).
3. **Equivalent rewrites** (each must preserve meaning for side-effect-free operands; apply only where the documented precondition holds, else skip the site): swap operands of `==` and `!=`; `assert a == b` to `assert not (a != b)` only when both operands are literals or names; `assertEqual(a, b)` to `assertEqual(b, a)`; rename local variables of the test function consistently (never names that are parameters/fixtures, globals, nonlocals, attributes or names used in nested scopes or string annotations); reorder adjacent independent assignment statements is NOT allowed (too risky): do not implement it; insert a no-op local assignment with a derived name. Operands containing calls, awaits, yields, walrus, comprehension side effects or attribute access on unknown objects are treated as possibly side-effecting for the operand-swap rules: document the exact rule.
4. **Mutant rewrites.** For a chosen assertion site whose expected side is a literal (int, str, bytes, bool, None, or a tuple/list of those): replace the literal with a third value that differs from the original, built deterministically from the seed (ints: original + nonzero offset; str/bytes: original with a derived suffix; bool: assertion negated; None: a sentinel string). The mutant must change exactly one site and nothing else.
5. **Variant pool (TR-GR-8).** `build_pool(source, seed, n_equivalents=4, n_mutants=4, eligible_sites=None) -> Pool`: deterministic for a given source and seed (derive all choices from SHA-256 of seed and site id; no `random` module global state, no time, no hash randomisation effects: sort every set before use); each variant records its kind, the site ids and rewrite names applied, and the SHA-256 of its text; variants are pairwise distinct and all differ from the original; every variant re-parses successfully; equivalents and mutants in one pool are drawn from the same rewritten base text so that a mutant differs from its paired equivalent only at the mutated site (TR-GR-7 groundwork: return that pairing). `eligible_sites` restricts mutants to the given site ids (the later base-failing-assertion finder supplies them). If fewer variants than requested are possible, return what exists and say so in the result.
6. **Output.** Deterministic JSON manifest (kinds, site ids, rewrites, hashes, counts, shortfalls) and variant files written atomically into an output directory that must be empty; no host values in any output. CLI: `python -m hermetic_mutants --test-file FILE --seed HEX --out DIR [--equivalents N] [--mutants N]`; exit 0, or 1 on error.

Tests: each rewrite on a small fixture with the expected output text; preconditions (a site with a call operand is not operand-swapped; fixtures are never renamed; a name used in a nested function is not renamed); mutants change exactly one site (compare syntax trees); determinism (same seed twice gives identical bytes; different seed differs); pool pairing property; hostile input (oversized, deeply nested expression, invalid syntax, non-UTF-8) gives the typed error; and a semantic check that is safe to run because the fixture is written by you: for a hand-written fixture test module with pure assertions, executing original and each equivalent with `exec` in a fresh namespace gives the same pass/fail per test function, and each mutant makes its target test fail.
