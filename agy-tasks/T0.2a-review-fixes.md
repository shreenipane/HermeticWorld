## Correctness (must fix)

### G1. Django `#N` references are Trac tickets, not GitHub issues
Django doesn't use GitHub issues. In `django/django`, `Fixed #30257` refers to **Trac ticket 30257**. Today a Django PR whose text says `Fixes #N` would be looked up as GitHub issue N, which gives a 404 or the wrong object. Django is 309 of the 500 Verified tasks.
- **Fix:** give `linked_refs` the PR **title** as well as the body, by changing its signature to `linked_refs(repo, title, body)`.
  - For `django/django`, every match of a ticket reference in the title or body gives a `trac` ref. A ticket reference is any of: the Trac URL; a closing keyword plus `#N`; or `Refs #N`, which Django uses for partial work on a ticket.
  - Never create a `github` ref for `django/django`.
  - **Parse the title for every repo, not only Django.** The live run found `sphinx-doc__sphinx-8721`, whose body has no closing keyword. Its link is only in the title, `Fix #8720: viewcode: …`, so today it gets `issue_source: none`, and its cutoff falls on a commit 11 minutes after the issue was opened.
  - Other repos keep GitHub semantics. GitHub has no `Refs` keyword, so `Refs #N` is **not** a link there.
  - Order: title matches first, then body matches. Deduplicate.
- **Tests:**
  - The django-11099 end-to-end test still gives Trac 30257, now found from both the title and the body and deduplicated to one ref.
  - A Django title `Fixed #123 -- x` with an empty body gives `[IssueRef("trac", 123)]`.
  - `Refs #7` in `pytest-dev/pytest` gives `[]`.
  - Use the new real fixtures `sphinx-doc__sphinx__pull_8721.json` and `sphinx-doc__sphinx__issue_8720.json`: `linked_refs` on the Sphinx title and body gives `[IssueRef("github", 8720)]`, and `fetch_issue_created` gives `2021-01-21T15:22:46Z`.

### G11. PR-template comments are parsed as real links (found by the live run)
The reviewer's live intake of `sympy__sympy-20590` picked up `Fixes #1234` from **inside an HTML comment** in SymPy's PR template: `<!-- ... e.g. "Fixes #1234" ... -->`. GitHub doesn't render comments, so they never link anything. This time it was harmless only because #1234 happens to be a PR (from 2012). Had it been an issue, `T_world` would have been set **8 years** too early.
- **Fix:** strip HTML comments (`<!-- ... -->`, non-greedy, across lines) from the title and body before matching, in `linked_refs`.
- **Test:** use the new real fixtures `sympy__sympy__pull_20590.json`, `sympy__sympy__issue_20567.json` and `sympy__sympy__issue_1234.json`.
  - `linked_refs` on the SymPy title and body gives exactly `[IssueRef("github", 20567)]`.
  - Add a SymPy end-to-end test like the pytest one. `hf_rows_page.json` now holds the real `sympy__sympy-20590` row (3 rows in total), so use it as-is. It should give `issue_created == 2020-12-10T08:44:03Z` and no "actually a pull request" warning.

### G2. An unresolvable issue reference fails the whole task
`fetch_issue_created` lets `HttpError` (for example 404 or 410, for a deleted or transferred issue) propagate, so `intake_task` fails.
- **Fix:** on `HttpError` with status 404 or 410, append a warning (`"issue <kind>#<n> could not be fetched (HTTP <status>); ignored"`) and return `None`. Other errors still propagate. The existing warning `"No valid issue reference resolved…"` then covers the cutoff consequence.
- **Test:** a fake `http_get` that 404s on the issue URL. The task completes, `issue_created` is null, and both warnings are present.

### G3. Cache writes aren't atomic
`http.py` and `load_verified` write cache files in place. An interrupted run leaves a truncated file that later reads as valid: a cut-off JSON, HTML page or `.jsonl` (a truncated `.jsonl` would **silently drop tasks**).
- **Fix:** write to a temp file in the same directory, then `os.replace` it into place. Add one helper, `_atomic_write_bytes(path, data)`, in `http.py` and reuse it in `intake.py`.
- **Test:** patch `os.replace` to raise. The final cache path must not exist afterwards, and no partial file may be left at the final path.

### G4. `load_verified` trusts a page with no `num_rows_total`
If the field is missing, the loop runs until it gets an empty page and the count check is skipped.
- **Fix:** raise `IntakeError` if the first page has no integer `num_rows_total` (fail closed).
- **Test:** a page without the field raises.

## Robustness and efficiency (must fix)

### G5. Every intake re-fetches an existing bare clone
Running `git fetch` on a bare clone made by `clone --bare` uses no refspec, so it doesn't update branches. It's also a network round-trip on every task.
- **Fix:** if `git cat-file -e <base>^{commit}` succeeds in the cached clone, skip fetching. Otherwise run `git fetch origin '+refs/heads/*:refs/heads/*' '+refs/tags/*:refs/tags/*'` and check again. If the base commit is still missing, raise `IntakeError`.
- **Test:** call `repo_dates` twice on the synthetic repo, with a spy on `run_git`. The second call issues **no** `fetch`.

### G6. `agent/` may keep stale files
`intake_task` writes into existing directories, so files left by an older run stay in `agent/`. The rule is that `agent/` holds **only** `problem_statement.md`.
- **Fix:** delete and recreate `agent/` (and `staging/`) before writing.
- **Test:** plant `agent/old.txt`, re-run the task, and check it's gone.

## Cleanup (must fix)

### G7. Duplicate rmtree handlers
`_handle_onexc` and `_handle_onerror` in `repo_sealer.py` have identical bodies. Replace them with one handler `def _make_writable_and_retry(func, path, _exc)`. Its third argument is ignored, so the same function works for both `onexc` and `onerror`.

### G8. Over-defensive status detection
`http.py` probes `status`, `getcode` and `code`. `urlopen` responses always have `.status`, so use `resp.status`.

### G9. Double warning channel
`fetch_issue_created` both appends to `warnings_list` and calls `warnings.warn`. Drop `warnings.warn` and make `warnings_list` a required argument. The task's `warnings` list is the single channel. Update the test.

### G10. Issue source worked out by string matching
`__main__.py` finds the issue source by matching `created_at` strings.
- **Fix:** have `intake_task` add a top-level `"issue_source"` to `task.json`: `"github#6189"`, `"trac#30257"` or `"none"` (the earliest resolved ref). The CLI then just prints it.
- **Test:** check the value in both end-to-end tests.
