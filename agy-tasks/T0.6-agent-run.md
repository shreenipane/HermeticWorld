## Part A: `python/hermetic_slice/model_client.py`

- `load_api_key(env=os.environ) -> str`: reads the file named by `HERMETIC_GEMINI_KEY_FILE` and strips it. Raises `ModelError` without echoing the contents.
- `ModelReply`, a frozen dataclass: `text`, `finish_reason`, `usage` (dict), `latency_s`, `attempts`.
- `GeminiClient(model, api_key, *, http_post=None, sleep=time.sleep, max_attempts=7, request_timeout=300)`:
  - `http_post(url, headers, body_bytes, timeout) -> (status, body_bytes)`. The default uses `urllib.request` and returns HTTP error statuses rather than raising. Retryable network errors (`URLError`, `TimeoutError`, `ConnectionError`) count as status 0.
  - `generate(system: str, messages: list[dict]) -> ModelReply`. Each message is `{"role": "user"|"model", "text": str}`. It uses `temperature` 0 and `maxOutputTokens` 8192.
  - **Retry** with backoff of 5, 10, 20, 40, 80 and 160 s, honouring a numeric `Retry-After`. Give up after `max_attempts` and raise `ModelError(status, scrubbed_body[:500])`.
  - A 200 response with no non-thought text, or a `finishReason` other than `STOP` or `MAX_TOKENS`, gives a `ModelReply` with whatever text there is. The loop decides what to do with it.

## Part B: `python/hermetic_slice/agent_loop.py`

A mini-SWE-agent-style **text protocol**: no tool calls, one bash block per turn.

- **`SYSTEM_PROMPT`.** You're a software engineer working in a Linux container at `/testbed`, which holds a Python repository. Your job is to fix the issue described by the user by editing the repository's source files. Then:
  - Every response must contain **exactly one** fenced ` ```bash ` block, holding one command or one `&&`-chained command, plus a short explanation.
  - Each command runs in a **new** shell, starting in `/testbed`, so `cd` and env vars don't persist.
  - There is **no internet**. `pip` can install only from a local mirror of the env's existing packages.
  - Don't modify or add tests, and don't touch `.git`.
  - Interactive tools (editors, pagers) don't work. Use `sed`, `cat <<'EOF'` and `python -c`.
  - When you're done, reply with exactly ` ```bash\necho HERMETIC_SUBMIT\n``` `. You can't continue after submitting.
- **`instance_prompt(problem_statement: str) -> str`.** The issue text, plus a reminder of the format and the workflow: explore, reproduce, fix, verify, then submit.
- **`run_agent(model, exec_fn, problem_statement, *, limits, trajectory_path) -> AgentResult`:**
  - **Inputs.**
    - `model.generate(system, messages) -> ModelReply`.
    - `exec_fn(command: str, timeout: int) -> (code, output)`. The runner adds the prelude and calls `world_exec`.
  - **`Limits`** dataclass: `max_steps=60`, `max_total_tokens=4_000_000` (sum of `totalTokenCount`), `max_wall_s=5400`, `command_timeout_s=180`, `max_output_chars=10000`, `max_consecutive_format_errors=5`.
  - **Parsing.** Find the bash blocks with `re.findall(r"```bash\s*\n(.*?)\n```", text, re.S)`.
    - Not exactly one block: send a format-error message as the next user turn ("Your response must contain exactly one ```bash block ..."). It counts as a step.
    - Block equal to `echo HERMETIC_SUBMIT` after stripping: stop with status `submitted`, **without executing it**.
  - **Observation.** `<returncode>{code}</returncode>\n<output>\n{output}\n</output>`. If the output is longer than `max_output_chars`, keep the first and last halves with a `\n[... N characters elided ...]\n` marker. A timeout (code 124 or 137) adds a line saying the command timed out after N s.
  - **History.** Keep the full conversation. When the total characters of the messages exceed 600 000, replace the `<output>` bodies of all but the last 10 observations with `[output elided to save context]`, recording that this happened.
  - **Exit statuses:**
    - `submitted`;
    - `step_limit`, `token_limit`, `time_limit`;
    - `format_error_limit`;
    - `model_error`, when the client raised after its retries.
  - **Trajectory.** Write `trajectory.jsonl` (append and flush per step): `{step, role, text, command, returncode, output_chars, elided, usage, latency_s, t}`. Never write thought text, and never write the key.
  - **`AgentResult`:** `status`, `steps`, `usage_totals`, `wall_s`, `submitted` (bool) and `error`.

## Part C: `python/hermetic_slice/extract.py`

`extract_patch(agent_container: str, sealed_image: str, work_dir: Path, *, max_patch_bytes=5_000_000) -> tuple[str, dict]`

The agent's tree is untrusted data, and the agent's `.git` is never used.
1. Stream `docker cp <agent>:/testbed -` (a tar) **to a file** in `work_dir`. Don't buffer it in memory; it can be hundreds of MB. If `run_docker` can't stream, add an optional `stdout_path` parameter to it. That's allowed, but keep existing callers unchanged.
2. Create an extractor container from the **sealed image** with `--network none --entrypoint /bin/bash`, named `hermetic-extract-<random>`, and keep it alive with `sleep infinity`. Copy the tar into it.
3. Inside the extractor (trusted git, from the sealed image):
   - Record the clean state: `git add -A && git -c user.name=hermetic -c user.email=hermetic@localhost commit -q --allow-empty --no-verify -m clean`, and save `CLEAN=$(git rev-parse HEAD)`.
   - Delete everything in `/testbed` except `.git`.
   - Extract the agent tar, excluding `testbed/.git` and everything under it, with `--no-same-owner --no-same-permissions`.
   - Then `git add -A` and `git diff --cached --binary --no-color --no-ext-diff --no-textconv $CLEAN`.

   Use `-c core.hooksPath=/dev/null` on every git call.
4. `docker rm -f` the extractor in a `finally` block.
5. If the patch is bigger than `max_patch_bytes`, raise `ExtractError("patch_too_large")`.
6. **Report:** `files_changed`, `files_added`, `files_deleted`, `patch_bytes`, `tar_bytes` and `sha256`.

The diff may contain symlinks or binary hunks. Don't filter them here; the grader's `validate_patch` rejects them.

## Part D: `python/hermetic_slice/runner.py`

`run_task(task_dir, *, model, grade_fn, run_dir, image_tag_format="hermetic/{id}:sealed", limits=Limits()) -> dict`
1. Read `task.json` and **only** `agent/problem_statement.md`. Nothing under `staging/` may reach the model.
2. Check that `index/index-report.json` and `world/probe.json` exist, and that `probe.json` has `all_ok: true`. If not, refuse with status `world_not_ready`.
3. `start_world(task, sealed_image, task_dir / "index", name=f"hermetic-run-{short_id}-{random}")`. Always `stop_world` it in a `finally` block.
4. `exec_fn = lambda cmd, timeout: world_exec(world, AGENT_PRELUDE + cmd, timeout=timeout)`.
5. Run `run_agent`.
6. After the agent ends, whatever its status, `extract_patch` from the agent container **before** `stop_world`.
7. `grade_fn(task_dir, patch_text, image=sealed_image, out_dir=run_dir / "grade")` returns the grade dict. If the patch is empty, still grade it: the official harness grades empty patches as unresolved.
8. Write `run_dir/patch.diff` and `run_dir/run.json`. `run.json` has schema `hermetic-slice-run/v0-unsigned` and these fields:
   - identity: `instance_id`;
   - fixed settings: `seal_level: "repo_only"`, `agent_mode: "H"`, `clock: "real"`, `grader_isolation: "clean_container"`, `deployment: "single_host"`;
   - task: `t_world`, `t_clock`, `base_commit`;
   - model: `model`, `limits`;
   - agent: `agent_status`, `steps`, `usage_totals`, `wall_s`;
   - images: `sealed_image` and `sealed_image_id` (from `docker image inspect`);
   - `digests`: sha256 of `seal/report.json`, `index/index-report.json`, `world/probe.json`, `trajectory.jsonl` and `patch.diff`;
   - `extract` report;
   - `grade`: `status`, `resolution`, `resolved`, and the f2p and p2p success and failure counts;
   - `status`: `completed` or `error`, plus `error`;
   - `date_leak_observed: null` and `notes`. Include "Phase 0: unsigned; transcript audit not run".
9. Return the record. Never print grader output to anything the model sees; the model is done by then anyway.
