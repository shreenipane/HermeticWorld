## What to build
1. **`hermetic-run/v1` statement (TR-ATT-1).** Typed struct with exactly the fields of §12.1, using the project enums for task class, seal level, agent mode, clock, grader isolation, deployment and run status. Only deterministic or digest values: there is no field for wall-clock time, host name, user, path or free text; digests are a validated newtype (algorithm prefix plus lower-case hex of the right length). Strict parsing (deny unknown fields, size cap), full validation (for example: Mode H carries the harness command log head and no gateway fields, Mode G the reverse; `repo_only` may carry a D5b warning list and `strict` must not; lists sorted and de-duplicated).
2. **Canonical encoding and run digest.** One canonical byte encoding (reuse the common crate's canonical JSON); the run digest is SHA-256 of it. Known-answer test with a full fixture and its expected digest; a test that field order and whitespace in the input do not change the digest; a test that any single field change does.
3. **`hermetic-transcript-audit/v1` (TR-ATT-2).** Subject = the run digest; label (derived or retrieved), confidence (bounded integer per-mille, not a float), evidence spans (log name, start, end; bounded count; validated ranges). Kept in a separate type and file so verifying a run record never reads it.
4. **In-toto / DSSE envelope.** Build the in-toto v1 statement (`_type`, `subject` with the digest, `predicateType` `hermetic-run/v1` or `hermetic-transcript-audit/v1`, `predicate`) and the DSSE envelope with the exact pre-authentication encoding (PAE) of the DSSE specification; known-answer test of the PAE bytes. Signing goes through a `Signer`/`Verifier` trait pair; provide only a deterministic test implementation in the test module and document in the README that real offline-key and Sigstore signing are a later task (no cryptographic signature dependency is available yet). Envelope parsing is strict and size-capped; verification recomputes the digest from the payload and refuses a mismatch, an unknown payload type or more than a named cap of signatures.
5. **Run status (§12.3).** A pure function from the grading inputs (R0, R1, R2, R3 results, NetVM malformed-frame flag, quota or volume cap hit, gate vs classifier disagreement, retrieved label in a sealed world, infrastructure failure, gate block) to the status, with a documented precedence, and a table-driven test covering every row of §12.3 and every precedence conflict.
6. **Score card (TR-ATT-3, §12.4).** From a list of validated run records: refuse to mix records whose version tuple (`spec_version`, `world_version`, `sealcheck_version`, grader image digest) differs; output benchmark and version, the tuple, seal level, clock level and agent mode (refuse mixtures), counts per status, per task class and per grader isolation, lists of excluded and repaired tasks, and the spread of `substrate_at_T`; deterministic JSON; known-answer test. Bounded number of records.
7. **README** for the crate: field table, what the record proves and does not prove (§12.5), and what is deferred (real signing, TEE quote verification).
