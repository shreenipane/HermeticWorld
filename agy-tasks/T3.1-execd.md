# Task T3.1: `hermetic-execd`, the guest PID 1 (TR-EXD-1 to TR-EXD-6)

In Phase 3 the agent runs in a Firecracker microVM. `hermetic-execd` is PID 1 of that VM: it sets the guest clock before anything writable is mounted, assembles the root, applies the run spec, serves commands over vsock, and freezes the disk at shutdown.

Design for testing on the host without root: all privileged effects go through one trait (name it `Sys`) with a real implementation (used only by the binary in a guest) and a recording fake used by tests. The boot, run-spec, RPC and shutdown logic are written against the trait and the RPC server against a generic stream/listener, so tests drive them over a Unix socket pair or in-memory pipes.

## What to build
1. **Kernel command line.** Parse `hermetic.t=<Unix seconds>` (required; decimal, bounded to a sane range; reject anything else), plus `hermetic.overlay=<device path>` and `hermetic.spec=<path>` with documented defaults. The reader caps the size of `/proc/cmdline`. A missing or malformed `hermetic.t` is fatal: execd writes nothing and powers the VM off with a distinct exit reason.
2. **Boot order (TR-EXD-1).** Exactly: (a) rootfs is already mounted read-only by the kernel; (b) `clock_settime(CLOCK_REALTIME, T_clock)` is the very first effect, before any mount, any file creation and any log line that could be written to disk; (c) mount the overlay disk read-write, create upper/work directories, assemble overlayfs over the read-only base, move the kernel's `/dev` (devtmpfs) into the new root, switch root; (d) mount `/proc`, `/sys`, `/dev/pts`, `/dev/shm`; (e) walk `/dev` without crossing mount points and without following symlinks and set every node's times to T_clock; (f) apply the run spec; (g) start the vsock server. A known-answer test asserts the exact ordered list of effects on the recording fake, and a second test asserts that if any step fails, no later step runs and the failure is reported. `/tmp` and `/run` are plain directories on the overlay: assert that no tmpfs is ever mounted there (TR-EXD-2).
3. **Run spec (§9.4).** Typed struct with strict (deny-unknown-fields), size-capped JSON parsing: environment variables, working directory, user and group (numeric ids), entry point and command, host name, `resolv.conf` content, resource declarations. Validate everything before applying anything (NUL bytes, name syntax, caps on counts and lengths, absolute normalised working directory). The spec is applied to every command: environment, cwd, uid/gid with supplementary groups cleared, in the order that actually drops privilege (groups, gid, uid). If the spec declares an entry point, it is started as a child and supervised.
4. **PID 1 duties (TR-EXD-3).** Reap all zombies (including orphans re-parented to PID 1); forward termination signals to the foreground child; allocate a pseudo-terminal when an exec request asks for one.
5. **RPC over vsock port 5000 (TR-EXD-4).** Length-prefixed frames with a hard cap on frame size; request types exec, upload, download, status, shutdown. The peer is the host (trusted more than the guest but still validated): malformed, oversized or truncated frames never panic and never allocate from an untrusted length; unknown request types are refused. Output is capped per command and per run (named caps; when hit, output is truncated with an explicit marker in the reply and the process is still reaped). Uploads are written atomically, cannot escape the guest root through symlinks or `..`, and are re-stamped to current guest time (never a time taken from the frame). Downloads are size-capped and refuse non-regular files. Exec has a wall-clock timeout from the request, bounded by a cap. Bound the number of concurrent connections and commands.
6. **Shutdown (TR-EXD-5).** On the shutdown request: signal every other process (TERM, bounded wait, KILL), wait for them to exit, `sync`, then `FIFREEZE` the upper filesystem through a descriptor opened at boot and kept open since, reply with a status frame, power off. Test the exact order on the fake, and that the freeze uses the descriptor kept from boot and not a new path lookup.
7. **Trusted re-boot hook (TR-EXD-6).** Document in the crate README how the same binary runs from an initramfs when a touched disk is booted again, and provide the code path (a `hermetic.initramfs=1` flag that makes execd refuse to execute anything from the overlay before the caller says so). Mark what needs a VM to verify.
8. **Logging.** execd logs only to the serial console/stderr, never to the disk, and no log line contains a host-derived value. Time in logs is guest time after step (b), and no time at all before it.

Also add `crates/hermetic-execd/README.md`: boot contract, frame format, caps table, what is verified on the host and what remains for the in-VM integration test (task T3.3).
