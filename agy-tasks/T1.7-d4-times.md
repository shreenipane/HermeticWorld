## Part C: D4 over an ext4 image
New module `ext4.rs` and subcommand `hermetic-sealcheck d4-image --image FILE --t-clock RFC3339 [--format json|sarif]`:
- Parse the superblock at offset 1024: check magic `0xEF53`, block size, inode size, inodes per group, group count, the 64-bit feature flag and descriptor size.
- Superblock times, each with its `_hi` byte when present: `s_mtime`, `s_wtime`, `s_mkfs_time`, `s_lastcheck`, `s_first_error_time`, `s_last_error_time`. A zero time is "unset", not a violation.
- Every in-use inode (use the inode bitmap; skip groups with `INODE_UNINIT`): `i_atime`, `i_ctime`, `i_mtime`, `i_dtime` (only for deleted inodes, which aren't in use, so skip), and with large inodes `i_crtime` plus the `_extra` epoch bits (the low 2 bits of each `*_extra` field extend the seconds; see the kernel's `ext4_decode_extra_time`).
- Any time > `T_clock` → `D4` Gate, channel `superblock` or `inode`, path `"<image>#inode/<n>"` or `"<image>#superblock/<field>"`, evidence naming the field and both times.
- Report a malformed image as one `D4` Info finding, channel `image_malformed`, never a panic.
- Exit code 2 on any gate, as `scan` does.
