## Part A: `cutoffs.py`

Implement exactly the spec's rules:

- `@dataclass(frozen=True) class Cutoffs`: `t_world: datetime`, `t_clock: datetime`, `discarded: tuple[DiscardedDate, ...]`.
- `@dataclass(frozen=True) class DiscardedDate`: `commit: str`, `author_date: datetime`, `reason: str`.
- `@dataclass(frozen=True) class FixCommit`: `sha: str`, `author_date: datetime`, `committer_date: datetime`.
- `compute_cutoffs(*, issue_created: datetime | None, pr_opened: datetime | None, fix_commits: Sequence[FixCommit], base_commit_time: datetime, repo_first_commit_time: datetime) -> Cutoffs`

Rules:
1. Candidates for `T_world` are `issue_created`, `pr_opened`, and each fix commit's `author_date` and `committer_date`. Use whichever exist.
2. An **author date** (only author dates, never the others) is discarded as implausible if either:
   - it is before `repo_first_commit_time` (reason `"before_first_commit"`); or
   - it is more than 90 days before **every** other candidate (reason `"outlier_gt_90d"`). "Every other candidate" means all remaining candidates except this one.
   - Record each discard in `discarded`.
3. `t_world` = the earliest surviving candidate. If no candidate survives, raise `ValueError`.
4. `t_clock` = max(`t_world`, `base_commit_time`).
5. Every datetime must be timezone-aware. Raise `ValueError` on naive datetimes. Normalise everything returned to UTC.
6. Don't tie anything to the PR's merge-base (see §4 for why).

## Part B: `gitutil.py`

There is one function for running git, and nothing else in the package may call `subprocess`:

- `run_git(args: list[str], *, cwd: Path, input: bytes | None = None, check: bool = True) -> bytes`
- It must isolate git from the user's machine config, which can change results (autocrlf, hooks, templates). Set these in the child environment:
  - `GIT_CONFIG_NOSYSTEM=1`
  - `GIT_CONFIG_GLOBAL` pointing at an empty file created once per process in a temp dir
  - `GIT_TERMINAL_PROMPT=0`
  - `LC_ALL=C`
- Pass args as a list. Never use `shell=True`.
- On failure, raise a `GitError` that includes the args, the exit code and stderr.

## Part C: `repo_sealer.py`

`seal_repo(src: Path, base_commit: str, dest: Path, t_clock: datetime) -> SealReport`

Requirements (TR-SEAL-1 to TR-SEAL-6):

1. **Never modify `src`.** Not its refs, config or objects. The tests will verify this by hashing `src/.git` before and after.
2. `dest` must not exist, or must be an empty directory. Create a fresh repo with `git init --template=` (an empty template means no sample hooks) and `-b sealed`.
3. Copy **only objects reachable from `base_commit`** into `dest`.
   - Hint: fetch the base commit by SHA from the local `src`, using `--upload-pack` to pass `-c uploadpack.allowAnySHA1InWant=true` to the upload-pack side. That way `src`'s config is never touched. Use `--no-tags`.
   - Resolve `base_commit` to a full 40-hex SHA first. Reject anything that isn't a commit.
4. **Tags** (§6.1). For each tag in `src`:
   - Peel it to its target. Drop it if the target isn't a commit.
   - Keep it only if that commit is an ancestor of `base_commit` or is `base_commit` itself.
   - An annotated tag must also have a tagger date ≤ `t_clock`. Recreate it in `dest` as the **same tag object**: fetch it, don't re-create it.
   - Record each kept and dropped tag with a reason: `"not_commit"`, `"not_ancestor"` or `"tagger_after_t_clock"`.
   - Fingerprint-checking tag messages is Phase 1. Leave a `# TODO(phase1): D-tier check on tag message` comment.
5. **Refs.** At the end, `dest` holds exactly `refs/heads/sealed` → `base_commit`, the kept tags, and `HEAD` → `refs/heads/sealed`. It must have:
   - no remotes;
   - no `FETCH_HEAD` or `ORIG_HEAD`;
   - no `logs/` (set `core.logAllRefUpdates=false` and delete `.git/logs`);
   - no stash, notes, `refs/pull`, `refs/original` or replace refs;
   - no `objects/info/alternates`;
   - no hooks (the `hooks/` dir is missing or empty).
6. **Working tree.** Check out `base_commit` into `dest`, then delete every `__pycache__` directory under it.
7. **Submodules and LFS** aren't supported in Phase 0. If `.gitmodules` exists at `base_commit`, or `.gitattributes` there contains `filter=lfs`, raise `UnsupportedRepoError` with a clear message, before writing anything to `dest`.
8. **Repack.** Run `git repack -a -d -f`, `git prune --expire=now` and `git commit-graph write --reachable`.
9. Then call `verify_sealed_repo(dest, base_commit, allowed_tags)` (below) and fail if it finds anything.

`verify_sealed_repo(repo: Path, base_commit: str, allowed_tags: Mapping[str, str]) -> list[str]` is a mini version of detector D1. It returns a list of human-readable problems, empty when the repo is clean. It must check:
- the set of all objects in the repo (`git cat-file --batch-all-objects --batch-check`) equals the set reachable from `base_commit` plus the kept tag objects;
- the refs listed by `git for-each-ref` match exactly what is allowed above;
- every forbidden path from step 5 is absent.

It must work on **any** repo, not just one produced by `seal_repo`. The tests will run it against an unsealed clone and expect problems.

`SealReport` is a frozen dataclass: `base_commit`, `object_count`, `kept_tags` (name → reason `"ancestor"`), `dropped_tags` (name → reason).

## Part D: CLI

`python -m hermetic_slice seal-repo --src PATH --base SHA --dest PATH --t-clock ISO8601`

It prints the `SealReport` as JSON. Exit codes: 0 on success, 2 if verification found problems, 1 on any other error.

## Part E: Tests (required, and they must pass)

The `conftest.py` fixture builds a synthetic source repo in `tmp_path`, with dates fixed through `GIT_AUTHOR_DATE` and `GIT_COMMITTER_DATE`:

- commits c1 → c2 → c3, where c3 is the **base**;
- c4 is the **fix**, on the main branch after c3, adding a file `fix.py` whose content is the unique string `SECRET_FIX_7f3a`;
- a lightweight tag on c2, an annotated tag on c1 dated before `t_clock`, an annotated tag on c2 dated **after** `t_clock`, and a tag on c4;
- a second branch with a commit after the base;
- a stash entry;
- a ref `refs/pull/1/head` → c4, and a ref `refs/original/refs/heads/main` → c4.

Tests must cover, at minimum:

- **Cutoffs:**
  - the earliest candidate wins;
  - `t_clock` is the base time when that is later;
  - each discard reason;
  - an author date isn't discarded when it's within 90 days of another candidate;
  - naive datetimes are rejected;
  - no candidates gives `ValueError`;
  - only author dates are ever discarded.
- **Sealer:**
  - after sealing, `SECRET_FIX_7f3a` appears in **no object** in `dest` (scan every object with `git cat-file --batch-all-objects --batch`) and in no file under `dest`;
  - the c4 commit is absent;
  - the kept and dropped tags match the expected reasons exactly;
  - `git log` in `dest` shows c1 to c3;
  - `src/.git` is byte-identical before and after (hash every file);
  - `verify_sealed_repo` returns `[]` on the sealed repo and a non-empty list on a plain `git clone` of `src`;
  - submodule and LFS repos raise `UnsupportedRepoError`, and `dest` is left untouched.
- **CLI:** one end-to-end test via `subprocess` with `sys.executable -m hermetic_slice`.
