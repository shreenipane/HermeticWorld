Statuses are `FAILED`, `PASSED`, `SKIPPED`, `ERROR` and `XFAIL`. Each parser maps a test id to a status, and when a test id appears twice the **last** line wins. Keep the source's quirks:
- **`_is_skip_summary`:** applies only to `SKIPPED` with `[N]`.
- **pytest:**
  - For `FAILED` lines, replace `" - "` with `" "` first.
  - Then take `split()[1]` as the id and `split()[0]` as the status.
  - Skip lines with ≤ 1 token.
- **pytest_options:** as pytest, but the id is rewritten by `(.*?)\[(.*)\]`. An option starting with a single `/` and containing no `*` becomes `/` + its last path segment.
- **pytest_v2:**
  - First strip `\[(\d+)m` and the control characters 1–31.
  - For `FAILED` lines, cut at the first `" - "`.
  - For a line that starts with a status, the id is the remaining tokens joined by a space.
  - Otherwise, a line that **ends** with a status gives an id made of all the tokens before it.

- **sympy:**

- **matplotlib:** as pytest, after replacing `MouseButton.LEFT` with `1` and `MouseButton.RIGHT` with `3`.

### C2. `validate_patch(diff, *, test_files: set[str]) -> tuple[str, list[dict]]`
Returns `(kept_diff, findings)`. This is §10's validation adapted to a diff, for Phase 0.

**Reject the whole patch** by raising `PatchRejected(reason)` on any of:

- named `*.pth`;
- anything under a `*.egg-info/` or `*.dist-info/` directory.

**Finding only, don't drop:** a new top-level module or package whose name is in `sys.stdlib_module_names` gives `{"kind": "stdlib_shadowing", ...}`.

### C3. `grade(task_dir, patch_text, *, image, out_dir, timeout=1800) -> dict`
1. Load `staging/eval.sh` and `eval_spec.json`. Check the sha256 of `eval.sh`, then run `prepare_eval_script`.
2. Validate the patch (`test_files` come from `staging/test.patch`). A rejection gives a result with status `patch_rejected`, and no container is created.
3. Create a container: `docker create --network none --name hermetic-grade-<random> --entrypoint /bin/bash <image> -c "sleep infinity"`. Then `docker start`. Use `docker cp` (via `run_docker` with a tar on stdin, or a temp file) to copy in `/tmp/patch.diff` and `/eval.sh`.
4. Apply the patch only if `kept_diff` isn't empty, using the official chain in order:
   - `git apply --verbose`
   - `git apply --verbose --3way`
   - `git apply --verbose --reject`
   - `patch --batch --forward --fuzz=5 -p1 -i`

   Before every attempt after the first, run `git checkout -- . ; git clean -fd`. If every attempt fails, try `git apply --check --reverse` ("already applied"). If that fails too, the status is `patch_apply_failed`.
5. Run `docker exec <c> /bin/bash /eval.sh` with a timeout. On timeout, kill the container and set status `timeout`. Capture the output in `out_dir/test_output.txt`.
6. **Always** `docker rm -f` the container, in a `finally` block.
7. **Grade the log** with the official `get_logs_eval` rules:
   - if `>>>>> Patch Apply Failed`, `>>>>> Reset Failed`, `>>>>> Tests Errored` or `>>>>> Tests Timed Out` appears in the log, it isn't parsed;
   - both the start and end markers are required;
   - parse the slice between the markers; if that's empty, parse the whole log;
   - if the status map is still empty, it isn't parsed;
   - a recorded `>>>>> Test Exit Code: N` with N ≠ 0, when the map has no `FAILED` or `ERROR`, gives "not parsed".
8. **Report:**
   - `_resolve_case`: exact id first; otherwise, if the id has more `[` than `]`, prefix-match, but only when every match agrees on pass versus fail.
   - `FAIL_TO_PASS`: success if `PASSED` or `XFAIL`; otherwise failure.
   - `PASS_TO_PASS`: success if `PASSED`, `XFAIL` or `SKIPPED`; otherwise failure.
   - Resolution: `RESOLVED_FULL` if both rates are 1, `RESOLVED_PARTIAL` if 0 < f2p < 1 and p2p = 1, and `RESOLVED_NO` otherwise. An empty list counts as a rate of 1.
9. Write `out_dir/grade.json` with schema `hermetic-slice-grade/v1`:
   - `instance_id`, `status` (`graded`, `patch_rejected`, `patch_apply_failed`, `timeout`, `log_unparsed` or `error`), `resolution`, `resolved` (bool);
   - `f2p` and `p2p`, each `{success:[...], failure:[...]}`;
   - `test_exit_code`, `removed_eval_lines`, `findings`, `patch_sha256`, `image`;
   - `network: "none"`, `duration_s`.

   The grader's stdout and stderr go **only** to these files (§11.1 one-shot rule). Nothing is returned to an agent.
