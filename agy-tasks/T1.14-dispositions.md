# Task T1.14: dispositions for tasks that fail the gate (§5.5)

You are the coding agent on Hermetic World. A task that fails the leak gate must never be dropped silently, because that changes the score's denominator. Each failing task gets a disposition: `repaired` or `excluded`.

Read first: `HERMETIC_WORLD_ARCHITECTURE.md` §5 (whole section, especially §5.5 and the gate/exit-code rules), §12.4 (score card); `TRD.md` (every requirement mentioning dispositions, the gate, D0, `problem_statement_redacted`, the score card); `crates/hermetic-common/src/world_manifest.rs` (`Disposition`, `DispositionKind`, `dispositions`); the sealcheck JSON output format (`crates/hermetic-sealcheck`, its JSON/SARIF writer and finding types); and the Python pipeline in `python/hermetic_slice` that runs the gate on a task (find where sealcheck results are consumed: `git grep -n sealcheck python`).

## What to build
1. **Decision logic** (put it where the gate result is consumed; Rust in `hermetic-common` or the sealcheck crate if the gate is Rust-side, else Python): given a task's gate findings, decide:
   - `excluded` when the leak *is* the task: a D0 finding whose leaking span cannot be removed without destroying the problem statement (spec: "the issue text is the fix"). Define the rule precisely from the spec, e.g. the redaction would remove more than a documented fraction of the statement or the span covers the whole fix; document the threshold as a named constant.
   - `repaired` when the sealer can remove the leak without changing the task: for D0, redact the leaking span from the problem statement (record `problem_statement_redacted` with the redacted spans' offsets and hashes, never the text), then re-scan; the disposition holds only if the re-scan is clean. For other detectors, `repaired` requires the sealer's removal plus a clean re-scan; if no automatic removal exists for that detector, the outcome is `excluded` with the detector named.
   - A task whose re-scan still fires is `excluded` with every detector that fired.
2. **Recording**: write each disposition into the world manifest's `dispositions` (new world version for `repaired`), and into a per-run `dispositions.json` listing every task with `{task_id, disposition, detectors, reason, world_version}`; tasks that passed the gate are listed as `clean`, so the denominator is visible. Never omit a task.
3. **CLI**: a subcommand or Python entry point that, given the gate output for a set of tasks, emits `dispositions.json` and a short summary (counts per disposition and per detector). Exit non-zero if any task lacks a disposition.
4. Update `PHASES.md` only by ticking the Dispositions checkbox with `(T1.14)` at the end; change nothing else in it.

## Tests
- D0 leak with a removable span: redacted, re-scan clean, `repaired`, `problem_statement_redacted` recorded without the leaked text.
- Issue text is the fix: `excluded`, D0 named.
- Non-D0 detector with no automatic removal: `excluded` with that detector.
- Re-scan still dirty after redaction: `excluded`, all detectors listed.
- Clean task listed as `clean`; output for N tasks always has N entries; sorted and stable.
- Malformed gate output: clear error, no panic, no partial file.
