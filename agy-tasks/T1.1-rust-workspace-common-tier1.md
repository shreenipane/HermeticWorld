## Part C: `crates/hermetic-sealcheck` (library + binary `hermetic-sealcheck`)

### C1. `diff` module: unified diff parsing
- Parse a unified diff into files and hunks: old and new paths, `/dev/null`, and `@@ -a,b +c,d @@` ranges.
- Lines are context, added or removed.
- Handle `\ No newline at end of file`.
- Tolerate `diff --git` headers with mode, rename and index lines.

### C2. `normalize` module (TR-SC-2)
- `normalize_line(&str) -> Option<String>`:
  - strip a leading diff marker (`+`, `-` or a space) when called in diff mode;
  - strip trailing `#` comments when they're outside a string literal (a simple quote-aware scan is enough);
  - collapse internal whitespace to single spaces and trim.
- **Trivial lines return `None`:**
  - fewer than 12 characters after normalising;
  - bare Python keywords (`else:`, `pass`, `return`, `try:`, `finally:` and so on);
  - lines made only of brackets and punctuation.

### C3. `fingerprint` module (TR-SC-1, TR-SC-2): tier 1 only
`FingerprintSet::from_task(gold_patch, test_patch, base_tree_root: &Path) -> Result<Self, ...>`, which builds:
1. **Lines:** hashes of the normalised added lines of the gold patch and of the test patch.
2. **Windows:** for every changed position in the gold patch, the hashes of the 2-line and 3-line windows **of the post-fix file** that span it.
   - Reconstruct the post-fix file by applying the gold hunks to the base file read from `base_tree_root/<path>`.
   - For new files, use the added lines.
   - Windows are joined normalised lines; skip a window whose lines all normalise to `None`.
3. **Removed-line markers:** for each line the gold patch removes, a hash of `"-" + normalised` (§5.2, diff-like text).
4. **Diff shape:**
   - a hash of `path + all hunk headers`;
   - a hash of the path plus the sequence of `+`/`-` normalised lines, without ranges.

**Weights:** each fingerprint belongs to a **hunk**, and the hunk's weight is spread over its fingerprints. A line fingerprint's weight is `1 / (1 + count of that normalised line in the base tree)`, which is rarity; windows use the minimum weight of their lines.

**Baseline subtraction (TR-SC-1).** Walk `base_tree_root`, skipping `.git`, and remove every line or window fingerprint whose hash also occurs in the base tree. Count line occurrences while walking, for the weights. The removed-line `-` markers never occur in ordinary source, so they survive (that's intended). Record how many fingerprints were subtracted.

### C4. `scan` module: D2 tier 1 and D0
- **`scan_tree(root: &Path, fp: &FingerprintSet, opts) -> Vec<Finding>`.** Walk every regular file under `root`, skipping `/proc`, `/sys` and `/dev` if `root` is `/`, and skipping files larger than `opts.max_file_bytes` (default 64 MiB). Each skip is recorded as an `info` finding, never silently.
  - Treat each file as one **unit**. Compute its line hashes and its 2/3-line window hashes. If it has diff-like lines (starting with `+` or `-`), also compute the after-change-view windows and the `-` markers (§5.2).
  - A unit **matches** when, for some hunk, the matched fingerprints carry at least `opts.hunk_threshold` (default 0.60) of that hunk's weight.
  - Also match on the diff-shape hashes.
  - Binary files (a NUL byte in the first 8 KiB) are skipped with an `info` finding. The binary tier is a later task.
- **`scan_problem_statement(text, fp) -> Vec<Finding>`** (D0): the problem statement as one unit, with the same rule. Then:
  - Code blocks inside it (```` ``` ```` fences) are also checked as separate units.
- **`Finding`** (serde):
  - `detector`: `D0` or `D2`;
  - `channel`, a short string such as `file`, `problem_statement` or `diff_shape`;
  - `path`;
  - `visibility`: `agent_visible` or `image_only`, given by the caller per root;
  - `severity`: `gate`, `review` or `info`;
  - `confidence`: the fraction of hunk weight matched, 0 to 1;
  - `hunk`: the index of the matched hunk;
  - `evidence`: up to 5 of the matched normalised lines, each truncated to 200 characters.

### C5. Output and CLI (TR-SC-8)
- **The command:** `hermetic-sealcheck scan --task <task_dir> --base-tree <dir> --root <dir> [--root-visibility agent_visible|image_only] [--format json|sarif] [--out <file>]`.
  - `--root` is repeatable, and each one carries its own visibility.
  - The task's problem statement is always scanned (D0).
- **JSON report:** `{schema: "hermetic-sealcheck/v0", instance_id, fingerprints: {lines, windows, removed_markers, diff_shapes, subtracted}, findings: [...], gate: bool}`.
- **SARIF 2.1.0:** a minimal valid log, with one run, `tool.driver.name = "hermetic-sealcheck"`, rules D0 and D2, and one result per non-info finding, each with `ruleId`, `level` (`error` for a gate, `warning` for review), `message.text` and a physical location.
- **Exit codes:**
  - **2** if any finding is `severity=gate` and `visibility=agent_visible`;
  - 0 otherwise;
  - 1 on errors.
