# Task T2.4: reproducible rootfs builder with D4 guard (TR-SEAL-7, TR-SEAL-8, TR-SEAL-12)

You are the coding agent on Hermetic World. A sealed world's root filesystem must be an ext4 image in which **no time is later than `T_clock`**, built **reproducibly** (sealing the same input twice gives a byte-identical image). Today the Phase 0 sealer only re-tags Docker images and leaves real file times (see `python/hermetic_slice/image_sealer.py`, "file mtimes not normalised"), so D4 flags every real image. This task adds the builder that fixes that.

Read first: `HERMETIC_WORLD_ARCHITECTURE.md` §6.2 (Root filesystem and substrate); `TRD.md` TR-SEAL-7, TR-SEAL-8, TR-SEAL-12; `python/hermetic_slice/__main__.py` (CLI style), `python/hermetic_slice/image_sealer.py` (conventions, errors), `python/tests/` (test style, fixtures, `conftest.py`); `crates/hermetic-sealcheck/src/main.rs` (the `d4-image` subcommand and its exit codes: 0 clean, 2 gate, 1 error).

## What to build
`build_rootfs(src: Path, out_image: Path, *, t_clock: datetime, world_id: str, size_mib: int | None = None, sealcheck_bin: Path | None = None) -> dict`, and CLI `python -m hermetic_slice build-rootfs --src DIR --out IMG --t-clock RFC3339 --world-id ID [--size-mib N] [--sealcheck-bin PATH]`.

1. **Staging copy.** Never modify `src`. Copy it into a temporary staging directory next to `out_image` (`shutil.copytree(symlinks=True)`, preserving modes; refuse special files: device nodes, FIFOs and sockets are skipped and listed in the result).
2. **Clean-up (TR-SEAL-8)** in the staging copy: delete `var/log/*`, `var/cache/*` (keep the directories themselves), `var/lib/apt/lists/*`, `root/.cache/pip`, every `.cache/pip` and `.cache/uv` under `home/*` and `root`, conda `pkgs` caches (`opt/conda/pkgs/*` and `*/miniconda3/pkgs/*`, keeping `urls.txt` if present), and shell histories (`.bash_history`, `.zsh_history`, `.python_history`, `.lesshst`, `.viminfo`) anywhere under `root/` and `home/`. Return the list of removed paths (relative, sorted).
3. **Determinism inputs.** `uuid = uuid.uuid5(NAMESPACE, "hermetic-rootfs:" + world_id)` and `hash_seed = uuid.uuid5(NAMESPACE, "hermetic-hash-seed:" + world_id)` with a fixed project namespace UUID constant. `SOURCE_DATE_EPOCH` = `t_clock` as integer Unix seconds. Image size: `size_mib` if given, else staging size × 1.3 + 64 MiB, rounded up to a whole MiB.
4. **Build (TR-SEAL-7).** Require e2fsprogs ≥ 1.47.1: parse `mke2fs -V` and raise a clear error naming the found version otherwise. Run `mke2fs -q -t ext4 -d <staging> -U <uuid> -E hash_seed=<hash_seed> -F <out.tmp> <size>M` with environment `SOURCE_DATE_EPOCH=<t>`, plus `E2FSPROGS_FAKE_TIME=<t>` and `TZ=UTC`, and nothing else inherited that could matter (start from a minimal env: `PATH`, `LANG=C`). Keep mke2fs's default feature set; determinism comes from the fixed uuid, hash seed and faked time, and the reproducibility test proves it. Write to `out_image.tmp`, rename on success, remove the staging directory always.
5. **Guard (D4).** Run `sealcheck d4-image --image <out> --t-clock <t> --format json` (binary from `sealcheck_bin`, else `$HERMETIC_SEALCHECK_BIN`, else `target/release/hermetic-sealcheck` or `target/debug/hermetic-sealcheck` searched under `~/hermetic/cargo-target/*/`; a clear error if none is found). Exit 0: pass. Exit 2: delete the image and raise `RootfsGateError` with the D4 findings. Exit 1 or anything else: delete the image and raise an error with sealcheck's stderr.
6. **Result** (also printed as JSON by the CLI): `image`, `sha256` of the image, `size_bytes`, `uuid`, `hash_seed`, `t_clock`, `source_date_epoch`, `removed` (from clean-up), `skipped_special`, `e2fsprogs_version`, `d4: "pass"`.

## Tests (`python/tests/test_rootfs.py`; skip the mke2fs-dependent tests with a clear reason when `mke2fs` is missing or older than 1.47.1, and the guard tests when no sealcheck binary is found)
- A synthetic tree whose files have mtimes **after** T_clock builds an image that passes D4 (the clamping works) and whose sha256 is reported.
- **Reproducibility (TR-SEAL-12):** building the same tree twice (different staging and output paths, different wall-clock moments) gives byte-identical images.
- A different `world_id` gives a different uuid and a different image.
- Clean-up removes exactly the listed caches and histories, keeps `var/log` and `var/cache` directories, and never touches `src` (compare a hash of `src` before and after).
- Special files are skipped and listed (create a FIFO with `os.mkfifo`).
- The version check rejects "mke2fs 1.47.0 (5-Feb-2023)" and accepts "mke2fs 1.47.2 (1-Jan-2025)" (unit test on the parser, no subprocess).
- Guard failure: monkeypatch the sealcheck call to return exit 2 with findings: the image is removed and `RootfsGateError` raised; exit 1 is an error too.
- CLI: `build-rootfs --help` works; a missing `--src` exits with an error.
