## What to build
Directory `images/kernel/` and Python module `python/hermetic_slice/guest_kernel.py` (standard library only) with CLI subcommands wired into `python/hermetic_slice/__main__.py`. You cannot download or compile a kernel in your sandbox; you build and test everything around it, and the owner runs the real build afterwards.

1. **`images/kernel/kernel.lock.json`**: the pin. Fields: kernel version (choose a 6.1.x long-term release that Firecracker supports for x86_64 guests; say which and why in the report), source tarball URL on kernel.org, `sha256` (put the literal string `"TO-BE-FILLED-BY-OWNER"`; never invent a hash), `release_date` of that exact version as RFC 3339 UTC (if you are not certain of the date write `"TO-BE-FILLED-BY-OWNER"`), `build_user` `"hermetic"`, `build_host` `"hermetic"`, the pinned builder container image reference with a digest placeholder, and the boot arguments. The loader refuses a lock that still holds a placeholder when asked to build, with a clear error naming the field.
2. **`images/kernel/hermetic.config`**: a config fragment (applied on top of the Firecracker-style microVM base config, which you also add as `images/kernel/base-x86_64.config`, minimal and commented). Required: version 5.10 or newer; `CONFIG_PTP_1588_CLOCK_KVM` off, and also off: `CONFIG_PTP_1588_CLOCK` users that read host time, `CONFIG_RTC_HCTOSYS`, loadable-module signature bypasses are out of scope; on: cgroup v2 controllers (cpu, memory, pids, io, cpuset, devices via BPF), all namespaces (user, pid, net, mnt, uts, ipc, cgroup, time is NOT required: explain your choice), overlayfs, ext4, netfilter with nftables and iptables-legacy compatibility plus TPROXY and conntrack, BPF syscall and cgroup BPF, virtio (blk, net, rng, vsock, console, mmio), vsock (`VSOCKETS`, `VIRTIO_VSOCKETS`), dm-verity, devtmpfs (not auto-mounted assumptions documented), `FHANDLE`, seccomp, `CONFIG_LOCALVERSION_AUTO` off and a fixed empty `CONFIG_LOCALVERSION`, `CONFIG_IKCONFIG` decision documented, random-number support for virtio-rng and RDRAND. Each line group carries a comment naming the requirement it serves.
3. **Config checker** `check_config(config_text) -> list[Finding]`: parses a final `.config` (bounded size, strict line grammar, never executes anything) and reports every required option that is missing or wrong and every forbidden option that is set (`=y` or `=m`). The required/forbidden table lives in one data structure that also generates the documentation table. CLI: `python -m hermetic_slice kernel-check-config --config PATH` (exit 0 clean, 2 findings, 1 error; JSON output with stable ordering).
4. **Boot arguments**: one function returns the canonical boot-argument string for a given `t_clock`: must include `clocksource=tsc tsc=reliable`, `hermetic.t=<Unix seconds>`, a read-only root (`ro`), `init=/sbin/hermetic-execd` (or the path T3.1 documents: read `agy-tasks/T3.1-execd.md`), `panic=-1`/reboot behaviour chosen and explained, console settings, and nothing that carries host identity. A checker rejects strings that lack the required arguments or contain forbidden ones (for example `clocksource=kvm-clock`, `no-kvmclock` handling explained, any `ip=` autoconfiguration, `rw`). Known-answer test for a fixed `t_clock`.
5. **Build script** `images/kernel/build.sh` plus `images/kernel/Dockerfile`: builds inside the pinned container (the host lacks flex and bison and must not need sudo): verifies the tarball's sha256 before unpacking, refuses to continue on mismatch, applies base + fragment with `scripts/kconfig/merge_config.sh`, runs `make olddefconfig`, runs the config checker on the final `.config` and stops on any finding, builds `vmlinux` with `KBUILD_BUILD_TIMESTAMP` = the lock's release date, `KBUILD_BUILD_USER`, `KBUILD_BUILD_HOST`, `SOURCE_DATE_EPOCH`, `LC_ALL=C`, `TZ=UTC`, a fixed build path inside the container, no network during the build, and writes `vmlinux`, the final `.config`, and a small JSON build record (version, hashes of inputs and outputs, no host name, no real time) to an output directory. Shell is strict (`set -euo pipefail`), quotes everything, takes no input from the environment except documented variables. The Python side builds the exact `docker` argument vector (a pure function, tested with a known-answer test; no shell string concatenation) and a `kernel-build` CLI subcommand that runs it.
6. **Post-build verifier** `verify_vmlinux(path, lock)`: without executing the kernel, extracts the Linux version banner from the image (bounded scan for the `Linux version ` string) and checks version, build user and host, and that the banner's date equals the lock's release date; reports a finding otherwise. Test with small synthetic files containing good and bad banners.
7. **Reproducibility hook**: `kernel-build --verify-reproducible` builds twice into different output directories and compares hashes (the function is tested with a fake builder).
8. **Docs** `images/kernel/README.md`: requirement table (generated from the same data as the checker; a test asserts the README table matches), how to fill the lock, how to run the build, what is and is not proven before a real build.

Tests in `python/tests/test_guest_kernel.py`: every checker rule (missing, wrong value, forbidden set, `=m` counts as set), hostile config text (oversized, NUL bytes, non-UTF-8, extremely long lines), lock validation and placeholder refusal, boot-argument known answer and rejections, docker argument vector known answer, banner verifier, and that `hermetic.config` + `base-x86_64.config` merged by a simple last-wins merge in the test satisfies the checker.
