## Part A: module `gitstore`

Read a git directory's object database with no external process.

- **Loose objects:** `objects/xx/yyyy...`, zlib-inflated through the `CountingReader` limits.
- **Packs:** `objects/pack/*.idx` (v2 only; v1 gives a `git_unsupported` finding) with its `.pack` (v2 or v3).
  - All object types, including `OFS_DELTA` and `REF_DELTA`, with delta base resolution.
  - A REF_DELTA base may be loose or in another pack.
  - **Limits, in `ScanOptions`:** delta chain depth at most 4096 with cycle detection; a resolved object at most `max_member_bytes`; the delta's declared result size must match what it produces.
  - A bounded cache of resolved delta bases (default 64 MiB). Don't load a whole pack's objects into memory.
  - Read packs by seeking or `mmap`-free positioned reads. A pack can be larger than RAM would like. No `unsafe`, so no `mmap` crate.
- **Object ids:** SHA-1 only. A repo with `extensions.objectformat = sha256` gives a `git_unsupported` finding at severity `review`.
- **Verification:** every commit, tree and tag inflated during the walk has its id recomputed; a mismatch gives a `git_corrupt` gate. Blob ids aren't verified during the walk, for speed. Unreachable blobs are hashed when scanned.
- **API:** enumerate all object ids across loose and packed storage; read an object by id; parse commits (tree, parents, committer time, message), trees (mode, name, id; gitlinks mode 160000 are recorded and not followed) and tags (object, type, tag name, tagger time, message).

## Part B: D1

`scan_tree` recognises a git directory: any directory holding a `HEAD` file and both `objects/` and `refs/` directories, whether named `.git` or bare. A `.git` **file** (a `gitdir:` pointer) gives a D1 gate, channel `git_pointer`.

Every finding uses detector `D1`, the root's visibility, and these channels. All are `gate` unless noted.

| Channel | Condition |
|---|---|
| `git_base_missing` | The task's `base_commit` isn't in the store |
| `git_unreachable_object` | An object not reachable from the base commit or an allowed tag. One finding per repo with the count and the first 20 ids, plus the per-object findings below |
| `git_ref` | Any ref outside the allowed set, from loose files under `refs/` and from `packed-refs`. This includes `refs/pull/*`, `refs/original/*`, `refs/stash`, `refs/notes/*`, and remote refs |
| `git_head` | `HEAD`, resolved, isn't the base commit |
| `git_tag` | A tag pointing at a non-ancestor, an annotated tag with no tagger date or a tagger date after `T_clock`, or a tag message matching a fingerprint tier |
| `git_state_file` | `logs/` holding any file, `FETCH_HEAD`, `ORIG_HEAD`, `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `BISECT_LOG`, `worktrees/`, `modules/` holding a repository, `objects/info/alternates`, `lfs/objects/` holding any object not referenced by the base tree |
| `git_commit_graph` | `objects/info/commit-graph` or `commit-graphs/` listing an id that isn't reachable. Parse the OIDL chunk. A commit-graph listing only reachable ids is allowed |
| `git_config` | A `[remote ...]` section, or a URL with embedded credentials |
| `git_unknown_file` | Any file under `objects/` that isn't a loose object, `.pack`, `.idx`, `.rev`, `.mtimes`, `info/packs` or a commit-graph file. This is a hiding place |

- **Allowed refs:** a branch under `refs/heads/` pointing at the base commit; a tag obeying the §6.1 rule.
- **Reachable** means walking from the base commit through parents, trees and blobs. Objects reached only through an allowed tag object are allowed too.
- **Shallow:** a `shallow` file gives an `info` finding, channel `git_shallow`.
- **Hooks** are out of scope for D1; they're scanned as ordinary files.

**Unreachable content scan (TR-SC-6).** Each unreachable blob, commit message and tag message is a scan unit. Run tiers 1 and 3 and the D9 content checks through `ContainerScanner::scan`, so a tarball committed to a dangling blob is opened too. Path syntax: `<gitdir>#<oid>`. Severity and channels are as usual for D2.

Reachable objects are **not** content-scanned: they're history at or before the base commit.

**The ordinary walk.** Inside a recognised git directory `scan_tree` skips `objects/` and its children, because `gitstore` covers them, and still scans everything else as ordinary files.

**Stray packs.** A git pack found outside a recognised git directory, on disk or in an archive, currently gets `container_skipped`. Replace that: walk the pack sequentially, resolve deltas by offset, and scan every blob as a unit with path `<file>#<offset>`. A REF_DELTA whose base isn't in the pack gives one `info` finding, channel `container_skipped`, per pack.

Add D1 to SARIF.

## Part C: D6

CLI gains `--oci-inspect <file>` (the JSON array `docker inspect <image>` writes) and `--oci-history <file>` (JSON lines from `docker image history --no-trunc --format json`). Each is optional. They're parsed tolerantly: an unknown field is ignored, and an unreadable file exits 1 like other usage errors.

Detector `D6`, all `gate`:

| Channel | Condition | Visibility |
|---|---|---|
| `oci_created` | The image's `Created` is after `T_clock` | `image_only` |
| `oci_history_date` | A history entry's `CreatedAt` is after `T_clock`. One finding with the count and the latest date | `image_only` |
| `oci_env` | An `Env` value holds a D9 signature or a fingerprint match | `agent_visible` |
| `oci_text` | A label, or a history `CreatedBy`, holds a D9 signature or a fingerprint match | `image_only` |

Dates parse as RFC 3339 and as docker's `2026-08-15 06:04:51 +0000 UTC` and `2026-08-15T06:04:51Z` forms. An unparseable date gives an `info` finding, channel `oci_bad_date`. Add D6 to SARIF.
