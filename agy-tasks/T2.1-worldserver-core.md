# Task T2.1: WorldServer core (TR-WS-1, TR-WS-2, TR-WS-4, TR-WS-5, TR-WS-6)

You are the coding agent on Hermetic World. WorldServer (Ring 3) is the host process that serves the sealed world (package indexes, git mirrors, archived pages) to one run. NetVM (Ring 2) forwards the agent's HTTP GET and HEAD requests to it as **fixed binary frames** over vsock; on the host, Firecracker exposes a guest vsock port as a **Unix domain socket**, so WorldServer listens on a Unix socket. This task builds the core: wire frames, limits, logging, sandboxing, and serving from a simple read-only store. The real package-world store format comes later (T2.3); design a `Store` trait so it can be swapped in.

## Part A: wire frames (`hermetic-common/src/wire.rs`)
Request frame (NetVM to WorldServer), all little-endian, total size capped at 16 KiB:
`magic "HWRQ" | version u8 = 1 | method u8 (1 = GET, 2 = HEAD) | flags u8 (bit 0: has range) | reserved u8 = 0 | request_id u64 | authority_len u16 | path_len u16 | range_start u64 | range_end u64 (inclusive; only meaningful with the flag) | authority bytes | path_and_query bytes`.
Rules: authority is lowercase ASCII host[:port] matching `[a-z0-9.-]+(:[0-9]{1,5})?`, at most 255 bytes; path_and_query starts with `/`, printable ASCII 0x21..=0x7E, at most 8 KiB; reserved and unknown flag bits must be zero; lengths must match the frame exactly. Any violation is `WireError::Malformed(reason)`.
Response frame (WorldServer to NetVM): `magic "HWRS" | version u8 = 1 | reserved [u8; 3] | request_id u64 | status u16 | header_count u16 | body_len u64 | headers (each: name_len u16, name, value_len u16, value) | body`. Header names lowercase ASCII token chars, values printable ASCII; caps: 64 headers, 8 KiB of headers, body per the run's limits.
Provide `encode`/`decode` for both, with a streaming reader that reads exactly one frame from a `Read` (never trusting a length past its cap before reading it). Fuzz-style tests: every single-byte flip and every truncation of valid frames gives `Malformed`/truncation errors, never a panic.

## Part B: the server (`crates/hermetic-world-server`, binary `hermetic-world-server`)
CLI: `hermetic-world-server --store DIR --socket PATH --log DIR --t-clock RFC3339 [--rate-rps N --burst N --max-requests N --max-bytes N]`.
1. **Startup order (TR-WS-1):** open the store directory and create the log files; bind the Unix socket; then apply **Landlock** (read-only access to the store, write access only to the log directory; refuse to start if Landlock is unavailable unless `--allow-no-landlock` is passed, and record that in the log) and **seccomp** (an allow-list built with seccompiler that denies `execve`/`execveat`, `ptrace`, `mount`/`umount2`, and `socket` for any family other than `AF_UNIX`; violations kill the process). Then accept connections. Factor the sandbox into a module with a function that tests can call in a child process.
2. **Per request:** decode a frame; a malformed frame ends the run: write a final log record with status `tampered`, close the socket, exit with a distinct code (3). Otherwise look up `authority + path_and_query` in the store.
3. **Store (`Store` trait):** `get(authority, path_and_query) -> Option<StoredObject { body source, content_type, extra headers }>`. Implement `DirStore`: files under `<store>/<authority>/<path>` (percent-decode the path, reject `..`, `//` tricks and NUL; the query string selects `<path>?<query>` stored with the `?` percent-encoded as `%3F` in the file name); optional sidecar `<file>.headers.json` with `content_type` and an allow-listed header map. Missing objects return `None`.
4. **Responses (TR-WS-4):** status 200 or 206 (range: honour `range_start..=range_end` clamped to the object; unsatisfiable range is 416 with `content-range: bytes */LEN`), HEAD returns headers without body. Always set `date` = `T_clock + elapsed since start`, in IMF-fixdate, and `content-length`. Never emit `memento-*`, `x-archive-*`, or a `server` header containing `pywb` even if a sidecar lists them (strip them). Misses: a 404 that looks like the real site: a per-authority sidecar `<store>/<authority>/.404.json` (status, content_type, body) if present, else a plain `404 Not Found` with `content-type: text/html` and a minimal body.
5. **Limits (TR-WS-5):** a token bucket per run (rate and burst from flags) that **delays** a request until a token is available and never refuses; per-run total caps on requests and response bytes: exceeding either ends the run with status `limit_exceeded` (log record, exit code 4).
6. **Logs (TR-WS-6):** an append-only log `<log>/requests.log`, one JSON line per event (`seq`, `elapsed_ms`, `request_id`, `method`, `authority`, `path_and_query`, `range`, `status`, `bytes`, `prev`, `hash`), where `hash = BLAKE3(prev_hash_hex || canonical_json_without_hash)` and the first `prev` is 64 zeros; fsync on the final record. A dedupe index `<log>/dedupe.json` mapping `(authority, path_and_query, status)` to `count, first_seen_seq, last_seen_seq`, rewritten atomically (temp file plus rename) every 100 requests and at exit. A `verify-log` subcommand checks the chain and reports the first bad line.
7. Concurrency: one connection at a time is enough for this task (NetVM multiplexes); requests on a connection are handled in order.

## Tests (offline; use tempdirs and a Unix socket; run the server in a thread or child process)
- Frame codec round trips and hostile-frame tests (above).
- GET, HEAD, range 206, unsatisfiable 416, miss 404 (default and per-authority), percent-decoding and traversal rejection (`/../`, `%2e%2e`, `%00`).
- Header rules: `date` is T_clock-based and advances; forbidden headers stripped even from sidecars.
- Token bucket delays but serves all requests (timing test with generous bounds); request cap and byte cap end the run with `limit_exceeded` and exit code 4; a malformed frame ends it with `tampered` and exit code 3.
- Hash chain: valid log verifies; editing, deleting or reordering a line is detected by `verify-log`.
- Dedupe index counts repeated requests.
- Sandbox, in a child process (spawn the test binary itself with an env var selecting the child role): after applying the sandbox, opening a file outside the allowed paths fails, writing into the store fails, `Command::new("true").status()` fails, and creating an `AF_INET` socket fails. If Landlock is not supported by the running kernel, the test prints a note and checks only seccomp.
