Benchmarks that
can’t be looked up.

Hermetic World is a time-sealed evaluation environment for AI agents. Each task runs in a world frozen at the moment the task was created, so the agent can only solve it by working it out.

View on GitHub ↗ Try the cutoff ↓

Linux x86_64 with KVM · Rust core, Python bridge · Status as of 2026-11-19: all phases built, end-to-end testing under way

Agents run in today’s world. Benchmarks come from the past.

When the answer already exists online, an agent can retrieve it instead of deriving it. The README and PRD cite a Cursor study of one model on SWE-bench Pro.

Figures as cited in the project’s PRD. Real escapes have also happened: DNS delegation out of an “offline” sandbox, answers left in task configs, and conftest.py hooks that force every test to pass.

Get to know Hermetic World.

Seal the answer. Seal the date. Grade in a clean room. Sign the result.

P1 · Answer seal

Nothing newer than the cutoff is reachable.

The sealer builds a frozen world for each task: the repo cut at the base commit, a root filesystem stamped at the cutoff, and a package mirror and web archive dated at or before it. sealcheck then scans for anything newer, before a run starts.

Move the cutoff ↓
sealcheck
  • ✓ repo history ends at base commit
  • ✓ package mirror dated ≤ cutoff
  • ✓ web archive dated ≤ cutoff
  • ✓ rootfs stamped at cutoff

Illustrative checks. See the spec for the real scanner.

P2 · Date seal

The clock inside never runs ahead.

Nothing the agent can read states a date later than the guest clock. This one is best effort, so it’s measured and recorded at one of three levels rather than promised outright.

See the three properties ↓
clock level
hiddenno clock to read
fakedclock pinned to cutoff
realactual time exposed

The recorded level is part of the claim.

P3 · Score integrity

The score depends only on the submitted work.

When the agent stops, a throwaway ExtractorVM pulls out its work. A clean GraderVM the agent never touched runs the tests three ways: normal, mutant and equivalence, to detect forged results.

Step through a run ↓
GraderVM
normalrun the tests
mutantbreak the code on purpose
equivalencecompare behaviour

Three passes, so a forged “pass” stands out.

Checkable claims

Every run ends in a signed record.

The host signs a record of everything: how well each channel was closed, the clock level, and the grading. Someone else can verify it, and readers of a published number can see what it does and doesn’t prove.

      Questions.
      
        
      
          
      What is Hermetic World?
      A time-sealed evaluation environment for AI agents. Each task runs in a world frozen at the moment the task was created, so the agent can only solve it by working it out, not by looking the answer up.
      
          
      What is sealcheck?
      The first component. Before a run, it proves that nothing created after the cutoff is reachable.
      
          
      Does it hide the cutoff itself?
      No. Hiding the cutoff is out of scope, as are undetectability, closing timing side channels, contamination in a model’s weights, and hiding the CPU generation.
      
          
      What do I need to run it?
      Linux x86_64 with KVM and Firecracker microVMs, with aarch64 later. Phases 0–1 need no VMs and run in containers. Phase 3 onwards needs KVM, either bare metal or EC2 with nested virtualization.
      
          
      What languages is it written in?
      The core is Rust. The Harbor bridge, package resolvers, test rewriting and classifier are Python.
      
          
      Is it ready to use?
      It’s early stage. Phase 0 is complete and Phases 1–3 are in progress. The CLI is planned, and only seal --task <id> has its arguments fixed so far.
      
          
      What’s not in the first release?
      Multi-container tasks, nested Docker, GPU tasks, and tasks that need the live internet by design.
      
          
      What’s the license?
      Apache-2.0.
